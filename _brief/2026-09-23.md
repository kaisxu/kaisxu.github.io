## [OpenAI 发布 GPT-6 Sol 与 Luna：不是新前沿，是一次五折降价](https://openai.com/index/introducing-gpt-6-sol-and-luna/)

继 9 月初的旗舰 Astra 之后，OpenAI 补齐了 GPT-6 的中档与小档。两者都是 105 万上下文、12.8 万最大输出，知识截止分别为 2026 年 4 月和 5 月。定价上 Sol 为每百万 token 输入 2 美元、输出 10 美元，Luna 低至 0.1 / 0.5 美元，相比 GPT-5.6 同档对折。OpenAI 自己在公告里写明「Astra 仍是我们各方面最好的模型」，并给出 Sol 在 AutomationBench 上 33.2%、单任务 0.27 美元的成本优势。Artificial Analysis 的独立复测却泼了冷水：智能指数与编码指数「与 GPT-5.6 持平」，降本几乎全部来自调价而非效率，Luna 的编码指数甚至倒退 2 分，两者在 GDPval-AA 上分别掉了约 100 和 75 Elo。

**推荐理由**：这是观察前沿实验室「价格战」阶段的标准样本——官方叙事与第三方复测的落差，比任何一组 benchmark 数字都更值得读。

## [Claude Opus 5.5 同日登场：Terminal-Bench 66.4%，价格再降两成](https://www.anthropic.com/claude-opus-5-5)

Anthropic 赶在同一天发布 Opus 5.5，主打大规模代码迁移与长程 agent 任务。Terminal-Bench 4.0 从 Opus 5 的 52.3% 提到 66.4%，CursorBench 46.6% → 57.8%，FrontierCode v1.1 48.0% → 54.4%，计算机操作 OSWorld 2.0 达 81.8%，覆盖 44 个职业的 GDPval-AA v2.1 拿到 1846 Elo。价格方面输入降到每百万 4 美元、输出 20 美元（各降 20%），缓存读取直降 60% 至 0.2 美元，官方称典型负载综合成本下降 40%，生成速度快 30%。已在 AWS、Google Cloud、Azure 三家云同步上线。

**推荐理由**：两家旗舰在同一天撞车本身就是新闻。与 GPT-6 对照读，能看清「涨能力」和「降单价」这两条路线当下各自走到了哪里。

## [GPT-6 Astra 破解了一封 2005 年以来无人攻克的 Enigma 密电](https://www.cryptocellar.org/bgac/the-mvueh-break.html)

这封代号 MVUEH 的德军电报发于 1941 年 7 月 10 日，编号 Nr. 172，共 82 个字母，自 2005 年公开以来一直未被破译。Carter Leffer 只是让 GPT-6 Astra 去尝试某个公开研究站点上的未破译电报，模型自行选定 MVUEH 为「最有希望的一封」，通过相似明文将它与另一封 SIPVX 关联起来，自己写了 Python 和 C++ 的 Enigma 模拟程序，用重复出现的地名 ROSENOW ROSENOW 作为 crib，两天内完成了系统性攻击。Crypto Cellar 研究负责人、老资格密码分析员 Frode Weierud 验证了密钥与明文，并指出模型的结论与他本人耗费数周的档案研究相符。

**推荐理由**：不是 benchmark，是一桩有独立人类专家背书的真实历史遗留难题。「两天 vs 数周」这个对比，比任何 agent 评测都更能说明问题。

## [微软 2007 年杀死了 FoxPro，有人用 Rust 和 WebAssembly 把它复活了](https://foxscript.org/)

FoxDev Studio 声称能直接打开并修改旧的 Visual FoxPro 工程，「不重写、不转换、不导出」。架构分四块：用 Rust 写、编译到 WebAssembly 的 64 位字节码虚拟机（对应原版的 p-code，但去掉了 32 位限制）；表单通过 React 从对象树直接渲染，可以只重绘单个控件；基于 fiber 的执行模型让程序在访问外部资源时让出而非阻塞，保留 FoxPro 的事件时序又不冻结界面；另有独立 32 位进程托管遗留 `.fll` 库。目前已实现语言参考中 1722 项里的 1534 项，报表尚未完成，超过 2GB 的表还需要新的格式规范。配套的 FoxScript 在原语法上加了 lambda 和 HTTP 服务能力。

**推荐理由**：被厂商抛弃十九年的语言仍有大量生产系统在跑。这是一份关于「如何给遗留系统一条不必重写的现代化出路」的严肃工程答卷。

## [Nathan Lambert 给美国国会的简报：开源模型的力量对比已经倾斜](https://www.interconnects.ai/p/the-current-balance-of-power-in-open)

这篇文章是 Lambert 为美国国会议员及幕僚准备的发言稿扩写版。核心数据：Hugging Face 累计下载量中国约 32 亿次、美国约 16 亿次，2:1；在 9 月 14 日的 Artificial Analysis 智能指数上，中国最强开源模型 GLM-5.3 得 45 分、Kimi K3 得 44 分，而美国最强的开源模型 Thinking Machines Inkling 只有 26 分，排在 15 个中国模型之后。他估算中国开源权重落后美国闭源前沿 2–5 个月，美国开源权重落后 6–9 个月，其中蒸馏只解释 1–2 个月。OpenRouter 上开源模型吞吐一年内从每周约 1T token 涨到约 80T，中国份额超过 80%。学术界的引用比例中 Qwen 已升至约 30%，超过 Llama 的 21%。

**推荐理由**：把「中美开源差距」从口号变成了可核对的数字。对判断该用哪家开源权重、以及政策风险往哪走，都是难得的一手材料。

## [Unreal Agent：把工具调用全部异步化，成本比 Codex 低四成](https://unreallabs.ai/blog/unreal-agent/)

这是一个 agent harness 而非模型。核心设计是完全异步的工具调用：每次调用立刻往事件日志追加一条「进行中」记录，执行在后台继续，结果稍后再追加，从而「免除底层模型管理等待、轮询和心跳的负担」。两个收益是用户可以随时插话干预而不必等工具跑完，以及单次模型轮次能塞进更多工具工作。全部用 GPT-6 Astra xhigh 测得：Terminal-Bench 4.0 得 57.9% 花费 1428 美元，而 Codex 榜单同为 57.9% 却要 2350 美元；DeepSWE 1.1 为 72.4% / 1367 美元对 Codex 的 69.0% / 1633 美元。以 Go 库形式发布，刻意不做子 agent 和工作流。

**推荐理由**：在模型能力趋同、大家都在拼单位任务成本的当下，harness 层的工程选择正成为真正的差异来源。异步工具调用这个切入点相当干净。

## [英伟达 Skill2Env：把 3.4k 个公开 Agent Skill 编译成 8k 个可执行 RL 环境](https://www.alphaxiv.org/abs/2609.reinforcing-agents-collective-skills)

思路是把社区写的 Skill 当作训练数据读：一个 SKILL.md 既是人们真正想让 agent 干的任务分布，也是指向真实工具与资产的指针，还包含了作者对「什么叫做得好」的判断。流水线用容器里的 Codex 把每个 Skill 拆成工作流并生成 Harbor 格式任务，附带程序化测试和行为 rubric，再用 Oracle 必须满分、空操作必须零分的双重门禁筛选。最终 7971 个任务横跨 13 个领域，软件工程只占不到四分之一。在 Qwen3.8-27B 上跑 300 步 DPPO，Terminal-Bench 2.1 提升 4.7 个百分点，自建的 S2EBench 提升 4.3 点。有意思的是加入 rubric 奖励反而拉低了 benchmark 分数，却让判官在 73% 的对比中认为其行为更贴合原 Skill。

**推荐理由**：「benchmark 分数下降但行为更对」这个结果本身就值得琢磨——它指出了当前 agent 评测只考核结果、不考核过程的结构性缺口。

## [谷歌用超网络在手机上现场生成 LoRA，绕开端侧微调的算力墙](https://www.alphaxiv.org/abs/2609.24979)

端侧模型受限于手机算力只能做小，而小模型恰恰最需要个性化。现有两条路都有硬伤：PEFT 要在手机上跑反向传播，算力上不可行；ICL 则拉长输入序列、抬高延迟，且上下文越长质量越差。这篇论文训练一个超网络，把用户的上下文 token 映射成一份适配该用户的 LoRA——手机端只需前向传播即可合成，合成完超网络参数就能从设备上删掉。架构上刻意复用设备上已有的那个 LLM 作为编码器底座，只额外挂一个可学习的 embedder LoRA。在 GEMMA3-1B 和 GEMMA1-2B 上测 LongLaMP 与 LaMP 数据集，ROUGE-1 全面优于 ICL 和 PEFT，多数配置下为超过四分之三的用户带来提升。

**推荐理由**：直指端侧定制化最现实的一道墙。文末引用 Karpathy 的「认知内核」构想——基座只留通用能力、个性通过可换插的 LoRA 承载——是个很清晰的技术路线图。

## [Cisco Talos 发现 CLOSEDQUORUM：让四个大模型投票决定下一步入侵动作](https://www.theregister.com/security/2026/09/22/windows-closedquorum-malware-uses-ai-models-to-autonomously-select-post-compromise-actions/5298435)

Talos 称这是首个公开记录的、用大模型做命令与控制的 Windows 植入物。这个 Go 写的后门依次询问 Gemini、DeepSeek、Qwen、Mistral 四家模型，由它们投票决定下一步动作，平票时依 DeepSeek、Qwen、Mistral、Gemini 的顺序裁决，部署后不再需要人类操作员。提取出的系统提示词让每个模型扮演「高级恶意软件策略师」，并限定只能从窃取（转储 LSASS、浏览器密码、加密货币钱包）、注入（进程镂空或 Early Bird）、持久化三个模块中选择。窃得数据经 AES-256-GCM 加密后发往 Discord，密钥按消息时间戳每日轮换。目前尚未观察到野外部署，但二进制痕迹指向 2025 年起的盗刷论坛帖子。分析师 Ryan Fetterman 的说法是：「它不会在攻击者睡觉时下线。」

**推荐理由**：把「agent 自主性」这件事放在攻防语境里看，是今年最值得警惕的一条技术线。Talos 建议的检测思路——同时访问多家模型接口且在碰 LSASS——也很有参考价值。

## [Z.ai 为偷传用户代码道歉，把整个 ZCode 开源了](https://www.theregister.com/security/2026/09/22/zai-says-sorry-for-slurping-up-your-code-open-sources-zcode/5298300)

Z.ai 的代码生成工具 ZCode 被发现会把用户的整个工作区——包括完整 git 历史——打包加密后上传至阿里云，而解密私钥只在 Z.ai 服务器上，用户既看不到也删不掉。研究者 Ferstar 追踪到触发点是 Repository Index 功能：在云端生成 Repo Wiki 之后就会上传，既无开关可关，隐私政策里也只字未提。Z.ai 周一致歉，称数据从未用于训练，已下线 Repo Wiki 并将项目整体开源，同时委托中国信通院和绿盟科技审计，两家均确认此前上传的数据已删除。Ferstar 确认开源代码中 Repo Wiki 确已移除，但批评 Z.ai 抹掉了提交记录和补丁前的上传源码。

**推荐理由**：AI 编程工具的索引功能正在成为一类新的数据外泄面。这次的处理方式——道歉、开源、第三方审计——也为同类事件立了个可以对照的参考点。

## [NightmareEclipse 的新 PoC 用占满磁盘的方式，把 Defender 冻结在过去](https://www.theregister.com/security/2026/09/22/nightmareeclipses-latest-zero-day-leaves-microsoft-defender-stuck-in-the-past/5298320)

这个名为 BigDiskBuster 的概念验证不去关闭 Defender，而是等更新开始后创建隐藏临时文件把剩余磁盘空间吃光，并开线程持续抢占，直到平台更新和安全情报更新失败，随后释放句柄归还空间——留下一个看似正常但特征库停滞的 Defender。它还会用限制其他进程访问的句柄打开 MRT.exe。作者 Abdelhamid Naceri 声称对所有受支持的 Windows 版本有效（未经证实），并承认代码「有点 buggy」。背景是他自 2026 年 4 月起因不满微软待遇持续公开零日；微软 5 月一度搬出数字犯罪部门被广泛解读为法律威胁，随后改口称无意追究安全研究者，但他的 GitHub 账号已被删除。此次无 CVE 编号，也无野外利用证据。

**推荐理由**：一桩典型的漏洞披露关系破裂事件，兼具技术巧思和治理争议。「让防护软件静默过期」这种攻击思路也比直接关停更难被察觉。

## [GeaStack：把 TypeScript 编译成原生代码，一路跑到 ESP32 和 RP2350](https://github.com/geastack/examples)

核心是 geatsc，一个 TypeScript 到 C++ 的编译器，原则只有一条：「静态类型的值一旦流入动态载体，就是缺陷而非退路。」所以这是真正的原生编译，不是 JS 引擎也不是 WebView 套壳（安卓是唯一例外）。应用写成 TSX 加 CSS，靠 `package.json` 里的 `gea` 清单声明入口与各平台兼容性。目标平台各有独立仓库：ESP32 与 RP2350 嵌入式板、macOS AppKit 与 iOS UIKit 外壳、把 Gea 节点映射到真实 Win32 子窗口控件的 Windows 渲染器，以及 Linux 与树莓派。另有通过 ANGLE 和 Metal 支撑真实 Three.js 的 WebGL 层，和一个把 `node:http` 编译成原生二进制的 node-compat。示例仓含 59 个应用（表盘、倾斜打砖块、相机工坊、Metal 着色器演示等）。需要注意授权：主体 MIT，但嵌入式板支持是 GPL-3.0-only。

**推荐理由**：给小型设备写界面这件事，长期在「原生难写」和「Web 套壳性能差」之间二选一。这个项目提供了第三种答案，而且示例数量说明它不只是个玩具。
