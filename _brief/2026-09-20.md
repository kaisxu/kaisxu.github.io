## [NYT 诉讼新简报曝光：微软总监称 AI 抓取是「人类史上最大规模的劳动盗窃」](https://www.tomshardware.com/tech-industry/artificial-intelligence/microsoft-director-called-ai-scraping-the-largest-theft-of-labor-in-human-history-while-openai-head-brands-chatgpt-an-existential-threat-to-publishers-revelations-come-from-legal-briefs-filed-in-nyt-lawsuit)

《纽约时报》诉 OpenAI 与微软案已进行近三年，时报方面近日申请简易判决，并提交了一份基于被告内部文件的法律简报——这些文件此前应两家公司要求处于封存或涂黑状态。简报引用微软应用科学总监 Brent Hecht 在 2023 年 1 月的内部备忘录，称大模型「吸干」所有人的作品将被视为「史无前例的惊人盗窃」和「人类史上最大规模的劳动盗窃」。微软自有数据显示，Copilot 使《纽约时报》的点击率相比 Bing 搜索下降了最高 93%，Hecht 将其称为「厄运循环」，并写道「终端产品威胁其核心供应商的经济基础是极不寻常的，但这正是我们为大模型业务的『内容供应链』所制造的局面」。OpenAI 的 ChatGPT 负责人 Nick Turley 则在内部沟通中承认 ChatGPT 对出版商构成「生存威胁」，且「随着能力提升会越来越具替代性」。

**推荐理由**：合理使用抗辩的核心在于被告是否预见到市场损害。这些内部原话恰恰证明他们预见到了，是本案迄今最实质的转折。

## [Plugin4Shell：所有主流 AI 编码助手共用的 0-click 远程代码执行链](https://www.theregister.com/security/2026/09/17/ai-coding-agents-0-click-rce-flaw-could-hand-attackers-keys-to-the-kingdom/5297335)

研究者披露了一条针对 AI 编码助手插件市场的供应链攻击。问题出在 SHA 固定（SHA-pinning）机制的验证不完整：助手会 checkout 市场所标注的那个 commit 哈希，但从不验证该 commit 确实落在预期的分支历史上。控制插件仓库的攻击者因此可以让 checkout 解析到恶意代码，而固定值看起来仍然被遵守。配合自动更新功能，这构成零点击远程代码执行——受害者无需任何操作。受影响的包括 Anthropic Claude Code、OpenAI Codex、Google Gemini CLI 和微软 Copilot。目前 Claude Code 2.1.179 与 Codex 0.146.0 已修复，微软 Copilot 与 Gemini CLI 尚未修补。

**推荐理由**：这类漏洞的杀伤力在于攻击面是「你信任的那份配置」。凡是在本地跑编码助手插件的人，今天就该确认版本号。

## [微软用 AI Agent 把 Copilot 运行时从 TypeScript 移植到 Rust，Token 成本 12 万美元](https://www.theregister.com/devops/2026/09/18/microsoft-agentically-ports-copilot-runtime-to-rust-for-120k/5297549)

微软用 GPT-5.6 Sol 与 Claude Opus 4.8 协同（按各自擅长的部分分工），在 14.5 周内把 43 万行 TypeScript 转成 80 万行生产级 Rust，期间发布 135 个版本，平均每天开 1.3 个移植 PR。人力投入约三周开发者时间，主要开销是 12 万美元的 token 费用。性能提升显著：单轮会话生命周期吞吐从每秒 7.55 次提升到 120 次（15.9 倍），10 客户端批量场景内存占用从 1383 MB 降到 126 MB。但团队明确指出「能编译就是对的」并不成立——他们处理了数十个通过了编译器检查的语义回归。最难的 session.ts（3 万余行）单文件耗时 25 小时，其中 56 分钟花在读文档、122 次澄清类工具调用。

**推荐理由**：难得有大规模 agentic 迁移公布了成本、工期和失败模式三项完整数据，比任何「AI 提效 N 倍」的宣传都更有参考价值。

## [CPython 让 Rust 变成可选项，绕开了内核社区踩过的坑](https://www.theregister.com/devops/2026/09/14/cpython-eases-rust-requirements-as-assimilation-continues/5296010)

CPython 维护者放弃了将 Rust 作为强制构建依赖的方案，改为可选支持：开发者可以选择用 Rust 写扩展模块，但构建 CPython 本身不强制要求 Rust 工具链。改变源于几方面的阻力——并非所有 Python 实现所在的平台都支持 Rust；Rust 的构建过程本身依赖 Python，会形成循环依赖；此外 Linux 内核引入 Rust 时的社区争议让维护者格外谨慎。Rust 项目经理 Tomáš Šedovič 表示新方案「绕开了人们提出的很多顾虑」。Guido van Rossum 也认可这一路线，认为「先从不那么核心的组件开始引入 Rust 听上去是个好计划」。文章强调其动机是内存安全而非性能。

**推荐理由**：同一个技术决策，内核社区走成了拉锯战，CPython 换个引入顺序就化解了。工程治理的差异值得对照着看。

## [Android 17 QPR1：自 Honeycomb 3.x 以来首次新增 API 却不开源](https://grapheneos.social/@GrapheneOS/117282080803799576)

GrapheneOS 指出，Android 17 QPR1 是自 Android 3.x（Honeycomb）以来第一个为应用开发者新增 API、却没有同步发布到 AOSP 的版本。这些新 API 目前仅 Pixel OS 独占，其他 Android OEM 无法获得。Honeycomb 是一段广为人知的历史——2011 年谷歌以「为平板赶工、代码尚未准备好」为由拒绝开源 3.x 源码，被视为 Android 开放性的第一道裂痕，直到 4.0 才恢复。十五年后同样的事再次发生，且这次伴随着谷歌今年早些时候把 AOSP 开发全面转入内部分支的一系列动作。差异在于：Honeycomb 是整个版本不开源，这次是 API 开源节奏与 Pixel 发布节奏脱钩。

**推荐理由**：Android 的开源承诺一向是靠惯例而非契约维系的。这条新闻的分量不在单次 API，而在惯例被打破后没有回退机制。

## [英伟达 200 亿美元收购 Groq 团队进入 DOJ 视野，但文章认为已经太迟](https://www.theregister.com/systems/2026/09/12/nvidias-groq-acquihire-is-on-the-dojs-radar-but-its-already-too-late/5295986)

英伟达 2025 年底斥资 200 亿美元获取 Groq 的 AI 加速器技术授权并招入其核心工程团队。交易被设计成「acquihire」而非常规并购——Groq 的推理服务业务名义上保持独立，但核心人才与技术资产已被剥离。《纽约时报》报道后，美国司法部启动反垄断调查，焦点是这种安排是否实质上消除了一个独立竞争者。多位参议员此前就主张这类「反向收并购」规避了监管审查。但文章认为即便交易被拆解，竞争损害也已被市场自身化解：英伟达 2024 年把 MGX 机架设计贡献给 OCP、2025 年通过 NVLink Fusion 开放互连授权，Cerebras、SambaNova、d-Matrix 等都能把各自芯片接进这套标准化基础设施。

**推荐理由**：真正的护城河不是那笔收购，而是英伟达把自家机架和互连标准送出去这步棋。反垄断工具对生态型锁定基本失效。

## [阿里 Qwen 团队《AI Office》综述：办公智能体的评测与真实需求严重错位](https://www.alphaxiv.org/abs/2609.evolution-ai-office-agents)

这份来自阿里 Qwen 大模型应用团队（联合北大、人大、南大）的综述提出「AI Office」统一框架，主张文档、表格、幻灯片三类智能体面对的是同一个问题——把用户意图翻译成一份可交付、可编辑、可审计的文件，衡量标准应是最终提交的产物而非对话回复。论文最有价值的是一张需求与评测的对照表：线上用户请求中「直接执行类」占 56.2% 却只有 4 个 benchmark 覆盖；「迭代修改」占 10.4% 仅 1 个；「格式与模板合规」约占 5% 却是彻底的空白区；而占比仅 2.8% 的问答理解类却有 6 个 benchmark。此外 30.5% 的 Excel 请求带有高或极高的验证风险，现有评测基本不覆盖。

**推荐理由**：把「用户到底在让 AI 做什么」和「学界在测什么」放在一张表里比对，这个角度对任何做 agent 产品选型的人都直接可用。

## [Brood War Bench：让大模型自主打《星际争霸》母巢之战](https://bw.swerdlow.dev/report)

Ben Swerdlow 搭建了一套让语言模型自主操控 1998 年发行的《星际争霸：母巢之战》的评测环境，共测试 19 种配置，覆盖 Codex Astra、Codex 5.6（Sol / Luna / Terra）、Claude 系列（Fable、Opus 5、Sonnet、Haiku）和 Grok 4.6 多个推理强度档位。评测采用循环赛制，每个配置在并行虚拟机上与其余所有配置对战，harness 记录完整的对局数据与 agent 日志，并按时间序列跟踪农民数、部队规模、建筑数和资源管理。结果 Codex Astra 在 xhigh 模式下达到 100% 胜率，Claude Fable 以 83.3% 列第三，Grok 最好的配置也仅赢下 11.1%。作者特别注明：所有 agent 都没有打出超过初学者的水平。

**推荐理由**：RTS 把长程规划、实时决策和资源管理压在同一个任务里，是现有 benchmark 覆盖不到的维度。作者对天花板的诚实标注也让结果更可信。

## [Lemmings 的漫长衰落：一个 1991 年现象级游戏是怎么被合同耗尽的](https://www.filfre.net/2026/09/the-lamentable-later-life-of-lemmings/)

DMA Design 1991 年的《Lemmings》曾被移植到 24 个平台，与《俄罗斯方块》《模拟城市》并列为休闲游戏的先驱。1993 年的《Lemmings 2: The Tribes》把技能扩充到 12 个部落共 60 种，反而因过于复杂劝退了新玩家。真正的转折是 1994 年：索尼收购 Psygnosis 后要求角色「适合做电视动画」、要有个体性格，与 DMA 的设计理念冲突，而工作室还背着六款游戏的合同义务。开发者 Mike Dailly 后来直言「Lemmings 3 有点烂……做它更多是为了了结合同，而不是真的想做个好游戏」。1995 年的《Lemmings 3D》强上三维带来镜头控制灾难，2000 年的《Lemmings Revolution》质量回升却因缺乏宣传无人问津。

**推荐理由**：同期的《俄罗斯方块》和《模拟城市》都成功过渡到了休闲游戏时代，只有 Lemmings 沦为怀旧符号。这个对照比单纯的怀旧更值得读。
