## [Mistral Large 4 发布：1T 总参数 MoE，量化后能塞进四块 GB300](https://www.alphaxiv.org/abs/2611.mistral-large-4)

Mistral 发布旗舰多模态 MoE 模型 ML4，总参数 1T、每 token 激活 52B，面向推理与长程 Agent 任务。技术报告里最值得一读的是一次"手术"：团队最初用滑动窗口注意力、跨层 KV 共享和 YOCO 把 KV cache 压到 1/16，预训练困惑度毫无异常，但 SFT 后 SWE-bench、BrowseComp 这类长程任务显著退化——他们称之为"agentic penalty"，最终做模型手术改回接近全注意力，再接 DeepSeek 稀疏注意力。预训练用 3840 块 GB200 跑 45 天、约 415 万 GPU 小时，MFU 36%。NVFP4 校准量化把 checkpoint 压到 606 GB，可部署在 4 张 GB300 上。成绩：Terminal-Bench 4.0 41%、FrontierCode 2.0 19.7%、AA Cyber Index 50.9%。

**推荐理由**：报告把一个少有人明说的教训写在了明处——语言建模损失相当，不代表长程 Agent 能力相当。KV cache 优化的代价第一次有了可量化的证据。

## [Gartner：到 2030 年，企业 Agent 工作流 90% 的步骤会跑在开放权重模型上](https://www.theregister.com/ai-and-ml/2026/11/03/open-models-can-do-90-of-agentic-work-at-a-twentieth-of-the-cost-of-a-frontier-llm-gartner/5307132)

Gartner 新报告《Open-Weight Models Will Run 90% of Enterprise Agentic Workflow Steps》给出一条明确的战略规划假设：典型运营工作流包含数百次例行执行——分类、工具调用、数据传递与校验、对账——其中九成步骤开放权重模型可以平价完成，每一个需要前沿推理的步骤对应上百个不需要的。成本上，对比同分数的最便宜闭源模型约为 1/4，对比"每步都用前沿模型"则低至 1/20（分析师承认开放模型更啰嗦、重试更多，实际差距约 5–6 倍）。但两位作者强调省钱只是副产品：真正的理由是"SaaS 公司被收购时，买家付钱买的很大一部分就是多年的工作流历史，每一次送往前沿 API 的例行调用，都把其中一片挪到了你的边界之外"。他们认为模型已是商品，价值在 harness。

**推荐理由**：把"用开源还是用闭源"从省钱话题换成了数据主权话题。对正在设计 Agent 架构的团队，这个论证比成本表更难反驳。

## [Revolut 把 Claude 换成 GLM 自托管：AI 编码账单降九成，56 张 B200 服务 2000 名工程师](https://www.theregister.com/ai-and-ml/2026/11/03/british-fintech-revolut-slashes-ai-coding-costs-10x-by-cutting-out-claude-and-going-self-hosted/5307345)

英国金融科技公司 Revolut 的运维与基础设施负责人 David Abitbol 披露，公司不到一年把 AI 编码推理成本砍掉约 90%，做法是把自托管模型设为默认。此前他们见过工程师单月烧掉 1000 到 10000 美元却看不到 ROI，于是设了严格预算上限，再转向自托管。GLM-5.1 自托管价格约为每百万 token 0.30 美元，约是 Codex 或 Claude Code 的十分之一；现已升级到 GLM-5.3，用 56 张 Nvidia B200 服务约 2000 名工程师，编码耗时改善 60%、交付前置时间改善 70%。工程经验相当具体：增益主要来自调参和 NVFP4 量化而非加卡；首 token 延迟必须低于 3 秒（"超过 5 秒我的 Slack 就会被炸"）；以及"长上下文是个骗局——能服务 100 万 token 不代表你需要，256K 才是真正要的"。GLM 是纯文本模型，UI 相关请求仍由路由分给 Gemini 或 GPT。

**推荐理由**：上一条 Gartner 的预测，这里有了一个 2000 人规模的实测样本。尤其"长上下文是个骗局"这句，是无数人花钱才买到的教训。

## [Postman 桌面版静默往 Codex 和 Claude Code 里装插件，还试图批准自己的启动钩子](https://github.com/postmanlabs/postman-app-support/issues/14370)

一位用户发现，仅仅打开 Postman，自己的编码 Agent 就被改了：系统里多出用户级 Postman 插件、一个 session_start 启动指令钩子、一个远程 MCP 连接、一个 Claude Code 插件和单独安装的 Postman CLI。Postman 自己的日志坐实了这点，明确记录 `"source":"auto-existing-upgrade","results":["claude-code:installed","codex:installed"]`。`~/.codex/config.toml` 被写入了 marketplace 源、插件启用项，以及钩子的 `trusted_hash` 与 `trusted_content_hash`——也就是说安装器试图替用户批准自己的钩子。该钩子的内容是指示 Agent 把广泛的 API 工作路由进 Postman。issue 开于 10 月 25 日，至 11 月 3 日已累积 26 条评论仍未关闭，有评论者实测验证了 Codex 的钩子信任机制可以被离线计算哈希后绕过。

**推荐理由**：Agent 时代的供应链攻击面不是模型，是配置文件。一个 API 客户端能把自己写进另一个工具的信任链，这条边界一旦默认可越，后面跟进的就不止 Postman 一家。

## [内存涨价逼回 8GB：微软让 Windows 11 在低配机上多撑一会儿](https://www.theregister.com/software/2026/11/03/microsoft-improves-windows-11-performance-on-8-gb-pcs-as-ram-prices-keep-climbing/5307382)

微软周二宣布"提高 8GB Windows 11 PC 的标准"，称内存管理改进让低端机响应速度提升最多 20%、多任务快 40%。具体改动相当朴素：活跃数据在换出到存储前多保留最多 2GB；Edge 已在后台运行时直接连接，启动快至多 33%；Teams 在 8GB 机器上默认启用效率模式；Widgets 改为按需加载；Edge 标签页休眠时间从两小时降到 15 分钟。背景是 AI 基础设施需求推高的内存荒——同一天的另一条新闻里，树莓派在上一轮涨价仅一个月后再次提价，16GB Pi 5 加 80 美元至 385 美元，超过发布价的三倍。微软在博文里还附了一份委托研究，称 2026 款 8GB XPS 13 的表现约等于 2021 款 16GB 机型。

**推荐理由**：数据中心抢走的内存，账单最终落在消费级硬件上。一边是 Copilot+ PC 要求 16GB 起步，一边是官方重新教 8GB 机器怎么活下去，这个分裂本身就是行业现状。

## [OpenAI 自建 Git 后端 Pando：推送延迟降至五分之一，每天吐出近 1PB](https://openai.com/index/scaling-git-at-openai/)

OpenAI 公开了 Pando——一个全新的 Git 仓库后端，在不改变任何人使用 Git 方式的前提下替换了 monorepo 的底层。动因是 Codex 改变了开发节奏：一个工程师同时有好几个变更在跑 CI，每次推送又触发多个任务拉取同一提交，去年底起拉取和推送变慢、合并失败，可靠性一度跌破 90%。Pando 的两个设计目标是水平扩展的写入（针对大量分支的并发推送）和最大化读吞吐。做法是每个分支独立协调更新，互不相关的分支可并行推进（代价是同时看多个分支可能看到不同时间点的状态）；以及跨请求复用 packfile 而非为每个客户端单独生成（客户端可能多下一些已有对象，但服务端几乎不用算）。上线后推送延迟中位数降为原来的约 1/5，每天提供接近 1PB 的 Git 数据。团队表示会把客户端改进回馈上游。

**推荐理由**：这是"Agent 规模的开发"对基础设施施压的第一份具体工程报告。可靠性跌破 90% 这个数字，比任何关于 AI 提升效率的宣传都更说明问题。

## [Nvidia 开源 Auto Ontology：给 Agent 补上"这个指标到底是什么意思"的那一层](https://github.com/NVIDIA/auto-ontology)

Nvidia 以 Apache 2.0 开源了 Auto Ontology，仓库已累积约 2800 星。它要解决的问题被 README 一句话点明：Agent 能检索文档、能查数据库，但可靠性才是瓶颈——"一个营收指标答得再快，数字错了就一文不值"。该库从企业元数据自动生成本体、跨系统调和互相打架的定义、把生成的 SQL 对照认证定义和血缘做校验并随答案返回出处，再通过 MCP、CLI 和 API 暴露给任意 Agent harness。技术栈是 FastAPI + LangChain 后端、Next.js 前端、Postgres + pgvector 存目录与向量，默认推理走 NVIDIA NIM（nemotron-3-nano-30b-a3b）。目前不接受外部贡献。

**推荐理由**：text-to-SQL 的准确率问题，业界试了两年发现不是模型不够强，而是语义层缺失。Nvidia 下场做这一层，说明它正从卖算力往上爬到卖企业 Agent 的地基。

## [丰田系 AISIN 展示把模型权重和操作系统一起放进片上内存的 SoC](https://www.theregister.com/systems/2026/11/03/toyota-shows-off-soc-that-stores-model-weights-and-its-os-on-integrated-memory/5307117)

丰田的主要持股公司、汽车零部件厂商 AISIN 联合东北大学展示了一款 16nm FinFET SoC：双核 Arm Cortex-A53 加 Mali-G31 GPU，内置 STT-MRAM，模型权重与操作系统全部存在片上。论点是现有芯片依赖外部内存存放模型，处理器与模型之间的流量拖慢了图像识别等端侧 AI，而 DRAM 眼下又贵得离谱。效果是从上电到内核启动 65.7 毫秒，比用外部内存快 38 倍，并能在片上跑 Tiny YOLOv3。为塞进有限的片上容量，团队做了 8 位与 16 位混合乘法架构，把权重数据从 17.7MB 压到 9.36MB（减少 53%）且保持 16 位精度。AISIN 尚未说明何时能量产。

**推荐理由**：在所有人卷大模型的时候，这是另一条路线的样本——模型小到能和 OS 一起住进 MRAM，冷启动变成毫秒级。physical AI 的约束条件和数据中心完全不同。

## [EPFL/NYU/哥大论文：让 Transformer 在推理时自己决定层的执行顺序](https://arxiv.org/abs/2611.03526)

Abdellah Rahmani、Sean McLeish 等人（EPFL、纽约大学、哥伦比亚大学、马里兰大学）提出 Library of Layers（LoL）。出发点是一个简单对照：程序员把同样的可复用原语——条件、循环——按不同顺序串起来实现不同算法，而现有语言模型架构永远以固定顺序执行各层。LoL 维护一个全局 Transformer 块库，推理时动态决定执行顺序；唯一的超参数是库的大小，由此在参数复用与稀疏之间连续过渡，把稠密、深度循环、MoE 三类架构的参数效率/FLOPs 效率权衡统一进一个族。文本预训练上与三类基线均有竞争力。更有意思的是在合成数独和迷宫数据上，模型会用不同的层序实现不同的解题策略，而且可以通过干预路由强制它对某个实例采用特定策略。

**推荐理由**：可干预的层序意味着"模型在用哪种策略"第一次变成了可读可写的量。这是架构创新与可解释性难得重合的一次。

## [1996 年不需要深蓝：一台奔腾 Pro 跑现代引擎，Elo 3300 碾压卡斯帕罗夫](https://nicholas.carlini.com/writing/2026/algorithmic-improvements-chess.html)

Nicholas Carlini 做了一次干净利落的算法进步量化实验。1996 年 IBM 为击败卡斯帕罗夫投入数百万美元造出深蓝：30 颗 120MHz 的 P2SC 处理器加 480 颗定制国际象棋 VLSI 协处理器，每秒分析超过两亿个局面，当时排世界超算第 259 位，棋力约 2700 Elo。Carlini 的反事实是：用 1995 年 11 月发布的 200MHz 奔腾 Pro、64MB 内存，移植一版 Stockfish，经典时限下估测 Elo 为 3300 ± 87——远超卡斯帕罗夫的接近 2800，而当年商用硬件上最强的引擎只有约 2300。他还给这台机器插了块 Realtek RTL8139C 网卡接上互联网，网页上可以直接和它对弈，并实时看到它的 VGA 文本屏。

**推荐理由**：把"算力进步"和"算法进步"分开称重的最漂亮的一次实验。同一代硬件上 1000 Elo 的差距，全部来自三十年的软件思想。

## [Flipper One 开启预售：主线 Linux、Wi-Fi 6E、千兆网口，还能插 M.2 的 5G 和 SDR](https://flipper.net/pages/flipper-one)

Flipper 团队公布 Flipper One 并开启 Kickstarter 前的预售。这次不是单片机玩具而是一台基于 RK3576 的 ARM Linux 计算机：内置 Wi-Fi 6E 和千兆以太网，通过 M.2 可扩展 5G 蜂窝模块、SDR 电台等。定位上最值得注意的是固件策略——团队声称运行完全开源、使用主线内核的 Linux 固件，不含二进制 blob，也不受厂商 BSP 限制，并已与 Collabora 合作把 RK3576 推进主线内核。硬件上采用双处理器架构，两颗处理器并行各管一部分子系统，这样即便 Linux 内核尚未就绪或已关闭，仍能从内置 LCD 直接控制 Linux 子系统。

**推荐理由**：一台公开承诺"没有 blob、跟得上最新内核、永不过时"的便携 Linux 多功能机。能不能兑现要等货，但这个目标本身在消费级 ARM 设备里就相当罕见。
