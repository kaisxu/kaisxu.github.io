## [Alphabet 单日蒸发 5000 亿美元：AI 摘要正在吃掉搜索自己的广告位](https://www.bbc.com/news/articles/cm9qzdqpxy48o)

Alphabet 季度总营收同比增长 25% 至 1276 亿美元、云业务翻倍到近 310 亿，但净利润下滑 25%，自由现金流为负 90 多亿——这是它上市以来第二次出现负自由现金流，且亏空较三个月前几乎翻倍。真正惊动华尔街的是公司承认：搜索页默认启用的 AI 摘要减少了可售广告位，直接冲击了占营收绝大部分的搜索广告。股价当日跌近 13%，市值从 3.97 万亿降至 3.46 万亿美元。同一组财报还藏着一个结构性拐点：[搜索收入 634 亿占总营收 49.7%](https://www.kadoa.com/companies/insights/google-search-below-half)，为 Alphabet 单列该项以来首次跌破一半，此前 31 个季度始终在 52.8%–62.0% 区间。同期亚马逊公布负 420 亿现金流、股价盘后跌 6%。

**推荐理由**：这是"AI 吞噬自己商业模式"从理论担忧变成财报数字的第一个标志性时刻，比任何泡沫论都更有说服力。

## [Mistral 开放 Large 4 权重：1 万亿参数，主打编码与防守方网络安全](https://mistral.ai/news/mistral-large-4-oss/)

Mistral 放出此前仅预览的旗舰模型 Mistral Large 4（代号 Le Chonk）全部权重，1 万亿参数、原生多模态，全程在欧洲基础设施上从零训练。预览后三周的额外强化学习把它推上开放权重编码榜首：Cognition 私有基准 FrontierCode 2.0 得 19.7% 居首，Terminal-Bench 4.0 从 28% 提升到 41%，在 Artificial Analysis 编码智能体指数上以 48% 追平 GLM-5.3，但每任务平均少用 47% token。另一条主线是防守型安全——Cyber Index 得 51% 为开放模型最高，同时对恶意网络请求的平均拒绝率达 96.6%。Booz Allen、Cisco、Cloudflare、CrowdStrike 与 ENISA 均参与了评测。

**推荐理由**：欧洲主权 AI 路线第一次拿出真正够得着前沿的开放权重模型，且刻意押注"只给防守方"这一叙事。

## [开放权重模型已能吃掉补丁窗口期：1000 美元攻破任一版本 Firefox](https://epoch.ai/publications/open-weight-models-patch-gap)

Epoch AI 证明 Z.ai 八月发布的开放权重模型 GLM 5.3 能够利用"补丁间隙"——安全修复已公开提交、但尚未推送到用户——自主构造可用攻击。实验中 9 月 17 日至 10 月 26 日之间发布的任意 Firefox 版本都可被攻破：受害者只需访问一个网页，攻击者即可读取其本地文件并外传，全程无需进一步交互。尽管上游刻意将安全补丁伪装成普通改进且不披露细节，GLM 5.3 仍能读代码分辨出哪些改动与漏洞相关。每个版本的攻击成本约 1000 美元，且使用过程中未触发包括 Z.ai 在内任何厂商的安全护栏。Mozilla 已在 10 月 27 日的 159.0 版中修补了过程中连带发现的未公开漏洞。

**推荐理由**：把"前沿模型有攻击能力"这一抽象风险，降维成了任何人花 1000 美元就能复现的具体流程，直接动摇开源项目的披露节奏假设。

## [一条畸形短信静默打瘫 Android 通话，连紧急呼叫一起掐断](https://smsofdeath.com/)

安卓电话子系统 `WapPushOverSms.decodeWapPdu()` 把 WSP 头长度按 `long` 读出后无边界检查地强转为 `int`，再直接用作数组大小。构造 5 字节 uintvar `88 80 80 80 00` 可解出 `0x80000000`，转为有符号 32 位整数即 −2147483648，分配负长度数组抛出未捕获异常，击杀 `com.android.phone`。消息以数据短信投递，收件箱无痕、发信号码不可见，受害者零交互。每条消息造成 1–2 秒断网并挂断进行中的通话（含紧急呼叫），运营商的未确认重投会反复触发，约 20 条即可让设备长期不可用，且消息滞留队列导致每次开机重新崩溃。Pixel 9 与多款三星复现率 100%，已在 2026 年 10 月安全更新中修补。

**推荐理由**：一个教科书级的符号转换疏漏，却能远程、静默地剥夺任意安卓用户拨打急救电话的能力，危害分级值得重新审视。

## [攻击者把 GitHub Issue 变成供应链武器：43 分钟打击 61 个公开仓库](https://www.theregister.com/security/2026/10/29/attackers-turn-github-issues-into-supply-chain-campaign-against-61-public-repos-in-less-than-an-hour/5306153)

Radware 研究人员发现针对 61 个公开 GitHub 仓库的至少 83 次攻击，受害项目包括 Google LangExtract、Trivy、Brave 浏览器和 MLflow。其中 77 次发生在 9 月 1 日的 43 分钟窗口内，其余 6 次在随后两分钟。攻击链是：在 issue、PR 或评论中用 HTML 注释藏入恶意命令（渲染页面上不可见），该事件自动触发仓库的 workflow，workflow 把攻击者控制的内容直接拼进 shell 源码执行，收集环境变量外传。攻击者使用了 74 个 GitHub 账号，多数有真实开发历史、很可能是被盗用的。研究者认为是单人协同操作，但无法确认是否真正拿到了仓库写权限。

**推荐理由**：不需要任何仓库权限、人人可发起，且恶意载荷在渲染视图中完全隐形——CI/CD 信任边界的一个系统性盲区。

## [Grace Blackwell 需要新调度器：同一批机柜榨出 27% 可用 GPU](https://skypilot.ai/blog/grace-blackwell-needs-a-new-scheduler)

NVL72 把一个机柜内的 72 块 GPU 全部接入统一 NVLink 域，跨节点带宽提升一个数量级，但收益完全取决于任务摆放——跨机柜的多节点任务仍受 InfiniBand 瓶颈限制，Hugging Face 实测张量并行从 NVLink 迁到 InfiniBand 训练吞吐下降 43%。难点在于机柜局部性会随时间劣化：硬件故障下线节点、任务在不同时刻结束，空闲容量被打散到各个机柜。SkyPilot 的做法是拓扑感知放置、GPU 故障的原地恢复、以及共享集群的自动碎片整理，官方数据是同样的机柜多出 27% 可用 GPU、NVL72 训练吞吐提升 14%。文中还讨论了为减少故障面而刻意缩小每机柜节点数的取舍。

**推荐理由**：机柜正在取代服务器成为调度的基本单位，这是 NVL72 时代 AI infra 最实际的一处范式变化。

## [Claude Code 把 15–20% 的 token 花在了三个词的状态栏上](https://gist.github.com/flamerix-ai/c3905705cc4205e5de3011fa2e74efce)

有人在 Claude Code 的 OpenTelemetry 导出里按 `query_source` 分组，发现名为 `agent_summary` 的请求开销超过主对话本身：占全部花费 16.4%（主对话 15.7%）、占全部 API 请求 19.7%，其中 96% 落在 Opus 上，输入输出 token 比约 9000:1。原因是每约 30 秒，每个后台智能体的**完整对话记录**会被发给该智能体自己的模型，只为生成"用 3–5 个词描述你最近的动作"这一行状态栏文字，结果既不进入模型上下文也不进入用户对话，自 2.1.232（2026 年 8 月）起默认开启且无开关。作者给出的缓解是一个约 70 行的 Bun preload，只包裹全局 `setTimeout` 并识别该计时器，不修改二进制。GitHub issue #86879 收录了另外四份独立测量，区间 18–26%。

**推荐理由**：可观测性数据戳破了智能体工具的隐性成本，也提出一个尖锐问题——UI 糖衣该不该花掉比正事更多的推理预算。

## [systemd 开始接受 Rust 组件，但立了三条硬规矩](https://www.theregister.com/os-platforms/2026/10/29/systemd-adds-support-for-rust/5306264)

Christian Brauner 宣布相关 PR 已合入，systemd 263 将支持用 Rust 编写的组件，首批落地的是 `systemd-keyring-setup` 及 keyring 相关辅助程序。三条限制值得注意：一是 Rust 只用于**新的叶子组件**，既不移植现有 C 代码，也不让任何其他组件依赖 Rust 写的部分——这不是重写 systemd 的开端；二是不用 Cargo，全部走 systemd 既有的 Meson 构建；三是 Rust 代码不得使用标准库（嵌入式 Rust 的常规做法）。门槛相当宽松：Rust 1.85（2025 年 2 月）、bindgen 0.71.1、Meson 1.4.0。Brauner 补充说团队本希望在 systemd 核心里用 Rust，但 Rust 目前对动态库的支持还不到位。

**推荐理由**：继内核之后，Linux 用户态最核心的那块基础设施也打开了口子，而"不许用 Cargo、不许用 std"的条件本身就说明了融合的真实难度。

## [LibreOffice 的"无 AI"招牌撞上了提交记录里的 LLM](https://www.theregister.com/ai-and-ml/2026/10/29/libreoffices-no-ai-stance-meets-llm-assisted-code/5306084)

文档基金会（TDF）把"不含 AI"做成了 LibreOffice 的卖点，9 月还专门发文宣称"无 AI 本身就是一项功能"。但有人翻出今年三笔致谢了 LLM 协助的提交：四月的两笔字号继承与 Calc 相对字号修复致谢 Claude 协助定位问题，九月的截图对话框"复制图片"按钮则用 VS Code 里的 GitHub Copilot 生成了 `BitmapTransferable` 类。TDF 在 Mastodon 上的回应是：核心开发者确实不使用 LLM，但基金会依赖更广泛社区的贡献，不会逐项列出禁用工具，只要求使用时披露并总体上不鼓励，且学生一律禁止；发言人进一步称此前关于 26.8 的声明针对的是用户功能而非开发过程。一位阿根廷开发者的评论被广泛引用："面包店宣布不在蛋糕糖霜里加石棉时，你不该指出他们已经在夹心里加了。"

**推荐理由**："无 AI"作为营销标签与工程现实之间的缝隙已经藏不住，这场争论会在更多 FOSS 项目重演。



苹果团队提出 SynthAPI 合成管线，沿工具、任务、工具所操作的数据库三个维度显式控制生成环境的多样性，随后在 458752 个任务、四种规模共 849 个训练模型上系统性地扫参，拟合出一条根据合成环境的规模与组成预测下游工具使用泛化能力的缩放律。核心结论是：随着数据预算增长，扩大**工具与数据库的多样性**比单纯增加任务数量更有效，提升数据复杂度带来的收益也更大。按此规律配比训练出的智能体，在四个评测基准上均超过了此前大规模工具使用与合成环境生成工作所训练的模型。

**推荐理由**：智能体训练长期靠直觉堆数据，这是第一次把"该造什么样的环境"写成可外推的定量关系，对预算分配有直接指导意义。

## [在树莓派 Pico 2 W 上跑世界模型：一个造游戏，一个在梦里玩](https://github.com/SheepSeb/tinyworldformer)

两个极小的神经网络同时跑在 RP2350 的 core 1 上：世界模型接收当前帧与动作，预测下一帧和奖励；执行器网络看着生成的帧选动作。两者在芯片上**从不接触真实游戏**——执行器只看世界模型吐出的画面，世界模型只收执行器给的动作。世界模型是循环 Transformer（同一个 block 复用权重以省内存）、int8 量化、2.6 万到 13.1 万参数、每帧 200 万到 800 万次乘加；执行器是两层 MLP、9 千到 1.6 万参数。已跑通 Breakout、Pong、Flappy 和一个 Doom 简化版，每个游戏用几百行 numpy 实现以便逐帧校验。预训练执行器可换成在板上从零学习的 stream-x 智能体，按任意按键即可接管自己来玩这个"梦"。

**推荐理由**：世界模型这类重计算范式被压缩到微控制器上仍然成立，既是漂亮的工程，也给小型化路线提供了一个极端参照点。
