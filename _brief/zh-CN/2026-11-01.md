## [一个邮箱地址拿下 GNU Savannah：他们本可以给 Bash 植入后门](https://hacktron.ai/blog/hacking-gnu-savannah)

安全厂商 Hacktron 披露，托管 Bash、Coreutils 等数百个 GNU 项目的 Savannah 代码托管站存在命令注入：注册时填入 ``a`touch${IFS}/tmp/savane-rce-proof`@attacker.example`` 这样的邮箱，GPG 密钥校验环节会把它直接拼进 shell 命令执行。拿到 Web 后端执行权后，他们把自己的账号提权为 superuser、冒充 Bash 维护者、并确认可以给上游 Bash 仓库添加具备 push 权限的 SSH 密钥；再借一个未打补丁内核的 OverlayFS 漏洞拿到 root 和 GNU 备份服务器。2026 年 5 月 11 日报告 FSF，后续审计把 Savane 的确认漏洞数累计到 26 个，现已全部修复。

**推荐理由**：xz 后门之后最接近成真的一次上游投毒——缺的不是技术门槛，而是一个志愿者维护的 PHP 表单校验。

## [窃密木马开始雇佣大模型当情报分析员：按「你值多少钱」给受害者排序](https://blog.talosintelligence.com/appraisal-by-ai-model-driven-victim-prioritization-in-the-volta-infostealer/)

思科 Talos 10 月 31 日披露 VOLTA-AUTODOXER：一款自删除的 Windows 窃密木马，在窃取浏览器密码、Cookie、支付卡、钱包助记词、Discord/Telegram/Steam 会话、Microsoft OAuth 令牌与云厂商密钥之后，还会用窃得的会话反向搜受害者的 Gmail 购物收据、外卖订单来佐证住址，打包成结构化证据交给 OpenRouter 上的模型，按系统提示词扮演「起草目标评估报告的取证情报分析师」，输出名为「WHAT THEY'RE WORTH」的变现价值分级和受害者的 OPSEC 评估。默认模型 claude-opus-4.6，检测到「I can't」之类拒绝就依次回退到 kimi-k2 和 gemini-2.5-flash，温度固定 0.2。整条链路没有攻击者自有基础设施。

## [Jepsen 测 ParticleDB：96 个问题，绝大多数只要一个节点一个客户端](https://jepsen.io/analyses/particledb-1.1.4)

Kyle Kingsbury 测试了号称「为 AI 负载设计」的多模型数据库 ParticleDB 1.1.4 至 1.1.18.11.rc-22，认定其「Full ACID」的宣称为时过早。96 个问题里从崩溃、死锁、数据丢失，到部分不可见且删不掉的行、`WHERE 4 = 5`、被 drop 的表以扭曲形态重现、列错位、字符串变整数。其中 93 个发生在健康的单节点实例上，无需注入任何故障。到 rc-22 版本只剩十个未解决，但默认的 occ 事务模式在正常运行下仍会丢失已提交写入，最强的 serializable 级别仍存在内部异常和 Lost Update。该库由 Orkes 用 Rust 从零编写，自称比 Postgres 快几个数量级且安全性相当。

**推荐理由**：「为 AI 工作负载重写一个数据库」正在成为时髦叙事，而 Jepsen 一如既往地提醒：正确性不会因为用 Rust 写就自动到手。

## [Meta FAIR + MIT 系统拆解循环 Transformer：什么时候该复用权重，什么时候别](https://arxiv.org/abs/2610.40325)

Meta Fundamental AI Research 与 MIT 的论文《How to Loop Your Transformer》在参数量、训练算力、自回归推理效率三个约束下联合研究权重复用。实验覆盖最大 1B 参数、155B token、1.07×10²¹ FLOPs、最多 32 次循环。结论是：固定参数预算下循环整个 Transformer 质量最好，而训练算力受限时循环中间若干层回报更高；增加循环次数并非单调有益，收益会饱和、反转甚至失稳。为此他们给每次循环加上小型低秩适配器，循环越多增益越大。针对循环带来的与次数成正比的解码减速，论文检验了 Parallel Loop Transformer 让各循环阶段跨相邻 token 并发的方案。

**推荐理由**：在「参数量不能再涨、显存也不想再涨」的现实约束下，权重复用是小型化最直接的一条路，而这是第一份把三类约束放在一起扫完的系统性消融。

## [一个只要几十 MB 内存的编码 Agent：Prospero 用 C++ 和 Dear ImGui 重写了 harness](https://nullprogram.com/blog/2026/10/31/)

nullprogram 的 Chris Wellons 对现有编码 harness 的 Web 技术栈和内存占用不满——他认为 harness 的本质不过是「curl 加上 popen()」，不该吃掉数 GB 内存——于是用自己的 C++ 风格配 Dear ImGui 停靠式界面写了 Prospero，资源占用比同类低约两个数量级。它不内置任何模型供应商，需自备 llama.cpp、本地部署模型或 OpenRouter/Anthropic/OpenAI API。功能上支持子 Agent 并发、Agent 间通信，通过 SSH 或 WSL 可把无头副本部署到其他主机；专业版内嵌的 x86/x86-64/ARM64 引擎覆盖 macOS、Windows、Linux，其中 Windows x86 版本能在 Windows XP 上运行，并带桌面控制能力。

**推荐理由**：本地模型终于能干活之后，harness 的开销反而成了瓶颈，这是一份对「Agent 工具链必须是 Electron」这一默认选项的有力反驳。

## [把语言模型塞进 512 字节引导扇区：开机即做梦，梦见一段 Linux 启动日志](https://github.com/kerlenton/bootgpt)

bootgpt 的 MBR 是 512 字节手写汇编，从随后 23 个扇区加载一个 11.5 KB 的 int8 模型，在 386 的 16 位实模式下直接运行——没有操作系统，没有 C 运行时。开机后机器开始「做梦」，逐字符生成带时间戳、PCI BAR 和 ACPI 事件的伪 Linux 启动日志，硬件全是虚构的。训练脚本把字符嵌入、单隐藏层和 softmax 全部量化为二的幂次缩放的 int8，使整个前向传播能用 `imul` 加一次 `idiv` 完成；脚本还会模拟汇编将要执行的精确整数运算（含 LCG 采样器），Python 输出与引导扇区输出逐字符一致。引导扇区只放代码，权重、字符串和词表都在数据扇区——这是把推理和 BIOS 调用一起塞进 510 字节的唯一办法。

**推荐理由**：极致小型化的教学样本——当整个模型必须和 BIOS 中断共用半 KB 时，量化方案、采样器和内存布局的每一个选择都无处遁形。

## [给电脑插一条电话线：USB-C 上的 LTE 调制解调器，通话音频直接走声卡](https://github.com/Koppar-AI/koppar-lte-modem)

一块 85×65 mm 的四层板，用一根 USB-C 线给计算机接上独立的手机号：板载 USB hub 向主机暴露三个标准设备——Quectel EC25-EUX 提供的网卡（LTE 数据，支持 3G/2G 回落，欧洲频段）和串口（`+CLIP` 来电显示、`AT+CMGS` 发短信、`ATA` 接听），以及 RP2040 把模块 1.8 V 的 PCM 接口电平转换后模拟出的 USB 声卡。插上 nano-SIM 后，计算机可以用耳机接听来电，也可以把这通电话交给脚本或 AI Agent 处理。无电池无屏幕，三颗 LED 指示网络、振铃与通话；5 V 供电经 3.8 V/3 A buck 以承受模块 2 A 的发射脉冲。KiCad 工程、Gerber、JLCPCB 贴片 BOM 与逐项对照数据手册的设计评审全部开源。

**推荐理由**：把「电话」降格成一个普通 USB 外设之后，Agent 接管语音通道就只剩软件问题了——这块板子是那条路径上缺失的硬件原语。
