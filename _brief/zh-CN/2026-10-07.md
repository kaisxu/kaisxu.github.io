## [Mistral 发布 Large 4：1 万亿参数开放权重，在欧洲自有机房用 3800 张 GB200 从零训出](https://mistral.ai/news/mistral-large-4/)

## [研究者称发现 KVM 虚拟机逃逸 0day，AWS、Google、Proxmox 全在射程内](https://www.theregister.com/offbeat/2026/10/06/security-researcher-claims-they-found-kvm-guest-host-escape-flaw/5301267)

安全研究者 Paulos Yibelo 在 X 上晒出一张赏金截图，称拿到了"完整虚拟机逃逸 0day（guest 到 host root，行业标准 hypervisor）"。赏金来自 Vercel 的 Sandbox 项目——该产品用 Firecracker MicroVM 给 AI 智能体做沙箱，底层正是 Linux KVM。Vercel CEO Guillermo Rauch 公开确认了 hypervisor 就是 KVM。目前公开信息仅此而已，相关邮件列表上无任何讨论，这在负责任披露的语境下反而是好事。KVM 的覆盖面是问题的全部分量：AWS 与 Google 的公有云、Nutanix、HPE、Proxmox 都建在它上面。修复是否需要停机尚不清楚，热补丁与实时迁移理论上可行。

**推荐理由**：guest-host 逃逸是虚拟化最坏的一类故障，而这次的触发场景恰好是当下增长最快的用法——给 AI 智能体当沙箱。

## [Chrome 应对 .gh / .sl / .as 三个国家顶级域注册局被劫持](https://blog.google/security/chromes-response-to-recent-cctld-registry-hijacks/)

攻击者攻破了加纳（.gh）、塞拉利昂（.sl）、美属萨摩亚（.as）三个 ccTLD 注册局，改写权威 DNS 记录并据此签发了覆盖多个 Google 域名以及其他组织域名的未授权 HTTPS 证书。Google 强调自身系统未被攻破，签发证书的 CA 也没做错什么——在 DNS 被完全控制的情况下，域名控制权校验本就会通过。Chrome 用 CRLSets 直接封禁了相关证书，并在查阅证书透明度日志后发现更多受害品牌，一并主动封禁。Google 建议域名所有者长期监控 CT 日志、并发布带 ACME 账户绑定的严格 CAA 记录——CAA 挡不住劫持进行时，但能阻止攻击者在 DNS 恢复后用缓存的校验状态继续签发新证书。

**推荐理由**：这是对 Web PKI 信任根基的直接打击：注册局一旦失守，CA 的尽职调查在技术上就无从生效，浏览器只能事后打补丁。

## [OpenAI 上线文本水印 textGrain，只在欧盟默认开启，且换 25% 同义词就基本失效](https://www.theregister.com/ai-and-ml/2026/10/06/openai-rolls-out-weak-sauce-watermarking-for-ai-text/5301257)

为满足欧盟《AI 法案》对生成内容机器可识别的要求，OpenAI 开始向 API 客户提供文本水印选项，并将在数周内对欧盟境内的 ChatGPT 与 Codex 输出强制施加。做法叫 textGrain：在逐 token 采样时周期性地挑一个同义词，使输出偏离无偏模型的统计分布，检测器再去找这份偏离。与全球统一启用 Google SynthID-Text 的 Anthropic 不同，OpenAI 只在欧盟默认开。效果也明显更弱：目标误报率 1% 时，200 词短文本只能检出 80% 的水印，400 词为 95%；数学和代码这类功能性文本更差。更要命的是鲁棒性——400 token 文本替换 10% 的词，检出率从 92% 掉到 66%；替换 25% 则只剩 17%。

**推荐理由**：合规与有效之间的裂缝被量化了：满足法条的最低成本实现，和真正能用于溯源的技术，之间差了一个数量级。

## [加密载荷骗过 GitHub Copilot CLI：密文绕过内容分类器，模型自己把密钥解了出来](https://www.theregister.com/ai-and-ml/2026/10/06/zombie-instructions-on-carefully-constructed-web-pages-could-trick-github-copilot-cli-into-sharing-secrets/5301206)

Adversa AI 把今年八月在 Grok 上发现的"加密上下文注入"（CCI）搬到了 GitHub Copilot CLI 上。原理是把恶意指令做成强加密密文，连同密钥材料和"请解密"的指示一起放在网页上——静态护栏只读文本、不执行文本，因此看不见密文里是什么；而 base64 或替换密码这类模型在训练中学过的编码则会被直接识破。攻击链里第一把密钥是假的，模板要求智能体读取本地 `.env` 等文件来拼出密钥，解密必然失败；于是它试第二把真密钥，拿到的指令是"去取另一个 URL 的上下文"，而那个 URL 里已经带上了刚才收集的密钥。成功与否取决于路由到哪个模型：微软自家 mai-code-1.1-flash 五成概率走完全程，两个 OpenAI GPT-5.6 模型均拒绝。GitHub 确认了该发现，但认定这不算产品漏洞。

**推荐理由**："模型路由到哪个后端决定你是否被攻破，而用户既不能选也看不到"——这是多模型智能体产品一个结构性的、无法靠提示词修补的风险面。

## [Polars 2.0：流式引擎转为默认，溢出到磁盘开箱即用，SQL 跑赢 DuckDB 与 DataFusion](https://pola.rs/posts/release-polars-2/)

本次大版本的核心是 `collect()` 默认切到流式引擎——代价是 join、group_by、unpivot 等操作不再保证行序，需要显式 `maintain_order=True`，这正是必须升主版本号的原因。同时默认启用 out-of-core：内存用到约 80% 开始溢写磁盘，默认磁盘预算 64GB，目前 sort、窗口函数和多数表达式已支持，join 与 group-by 在路线图上。SQL 被提升为一等公民，配合连接重排序、公共子计划消除、动态谓词与 bloom filter 等优化器改进，在 TPC-H 与 TPC-DS 基准上，除一项外全面领先 DuckDB 1.5.6、DuckDB 2.0 alpha 与 DataFusion 54.0。另新增对应 Arrow MapType 的 `Map` 数据类型。

**推荐理由**：Python 数据栈里最重要的 Rust 实现换上了流式默认值，"内存装不下就跑不动"这个长期约束在单机上基本解除了。

## [OpenAI 推出 Decisions API：只回答判断题、选择题和打分题，比 Responses 快十倍](https://developers.openai.com/api/docs/guides/decisions)

新的 `POST /v1/decisions` 端点进入公测，目前只支持 `gpt-6-luna`。它接受文本、图像或两者，返回三类带类型的答案：`predicate` 给出条件为真的概率（0 到 1）、`choice` 从给定集合里选一个、`score` 按有序等级打分并返回按概率加权的索引均值——因此分数可以落在两档之间。一次请求可带多个问题，共享同一份输入证据，响应按问题名回填。官方给出的定位很明确：需要生成符合自定义 JSON schema 的对象时用 Structured Outputs，需要模型发起带参数的工具调用时用 function calling，而分类、路由、排优先级这类"只要一个判断"的场合用 Decisions。

**推荐理由**：把 LLM 当分类器和路由器是智能体流水线里最高频、也最浪费的一类调用，专门的低延迟端点意味着这层用法正在被产品化。

## [Erdős 问题网站关闭评论区：AI 证明把人挤走了](https://www.erdosproblems.com/forum/thread/blog:9)

站长 Thomas Bloom 宣布对 erdosproblems.com 做出一系列改动。该站 2023 年 5 月上线，现收录 1221 个问题、9000 多条评论、近 2000 注册用户，日均独立访客一到两万。2025 年 8 月加的评论功能曾带来一轮繁荣：讨论、纠错、补文献、促成新合作。但这股活力没能持续，而 AI 极大加速了衰退——如今评论区的主要用途变成了发布 AI 生成的证明，往往不附任何解释，只为抢一个"越来越没有意义的"优先权。Bloom 认为这类仓库应该存在，但不该和一个旨在呈现问题脉络与人类理解现状的站点混在一起："没人会把餐馆开在屠宰场里。"他给自己定的准则改写自陶哲轩博客引用的 Po-Shen Loh 公理：这个站点应当让对 Erdős 式数学感兴趣的人类社群繁荣。

**推荐理由**：当 AI 能批量产出正确但无人理解的证明，受损的不是正确性而是数学社群本身——这是第一个为此动手改规则的一线站点。

## [把基座模型的回答开头固定成 ".\n\nOkay"，MATH-500 准确率从 42% 跳到 78%](https://www.alphaxiv.org/abs/2610.06851)

MIT 与 UC Berkeley（作者含 Alexei Efros、Sewon Min）研究了训练数据如何在回答的起始 token 与随后的推理行为之间建立关联。结论相当反直觉：只要把基座模型回答的开头强制固定成某个"线索 token"，它在数学和编程上的表现就能逼近经过强化学习训练的同款模型。Olmo-3-7B 的 MATH-500 pass@1 从 42% 升到 78%，Qwen3-14B 用 "Alright," 从 72% 升到 87%。进一步地，强化学习所做的事，很大程度上正是提高这些线索出现的概率——固定线索就能收回 RL 相对基座的多数增益。论文还通过编辑训练数据做反事实实验，证明是哪些数据决定了哪些 token 能触发推理，并发现同一机制也左右模型的拒答与顺从行为。

**推荐理由**：如果 RL 的主要作用是调高几个开场白的概率，那么"推理能力"有多少是新学来的、多少是原本就在基座里只差一个开关，需要重新算账。

## [openTPU：AI 设计的开源加速器，在一张二手 Kintex-7 PCIe 卡上跑 Qwen3 与 Gemma 4](https://github.com/FeSens/openTPU)

一个把 RTL、指令集、位精确模拟器、kernel 语言及其编译器、主机驱动与 profiler 全部塞进同一个小型 monorepo 的项目，自称"由 AI 开发的开源 AI 加速器"，用意是回答两个问题：AI 智能体在硬件设计上能走多远，以及它们能否造出跑自己推理的芯片。设计跑在一张浪潮 YPCB-00338 卡（Xilinx Kintex-7 xc7k480t，双 DDR3 通道）上，实测十个现代模型的真实权重，且板卡输出与模拟器逐 bit 一致。LFM2.5-230M 四比特量化下解码 85.8 tok/s，Qwen3-0.6B 为 31.3 tok/s，Phi-4-mini(3.8B) 6.56 tok/s；DRAM 带宽利用率普遍在峰值的 82%–94%。

**推荐理由**：从 Python 里的一次 matmul 一路读到导线的完整栈很少见，何况它还在一张老 FPGA 卡上真跑出了可用的 token 速率。

## [往 hosts 文件里加一行，Leopard 上的 iChat AV 又能打视频电话了](https://blog.pipetogrep.org/2026/09/11/resurrecting-ichat-audio-and-video-conferencing/)

2003 年 WWDC，苹果随 G5 和 OS X 10.3 一起发布了 iChat AV 与那台"过度工程"的 iSight 摄像头，在 MSN Messenger、Yahoo! Messenger 和 AIM 当道的年代，它是消费级音视频会议里罕见的真·领先。作者让这套东西在今天的互联网上重新工作：在跑 Leopard 或 Snow Leopard 的老 Mac 的 `/etc/hosts` 里把 `configuration.apple.com` 指向 `157.230.2.213` 即可——前提是路由器做端口保持型 NAT（多数都是）；pfSense、OPNsense 这类 BSD 路由器需要在出站 NAT 设置里手动开启源端口保持。Tiger 和 Panther 未经测试。

**推荐理由**：二十年前的协议之所以还能活，仅仅因为它依赖的是一个可被重定向的配置端点，而不是一座已经关停的云——这恰好是现在的产品普遍不具备的性质。
