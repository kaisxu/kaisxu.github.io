## [微软 AI Frontiers 解散：创始负责人出走，直指「只做规模、不做研究」的路线](https://hunch.net/?p=13764006)

John Langford 发文宣布，他 2023 年参与创建的微软研究院 AI Frontiers（约 50 人）已经终结。该组织的产出包括 Autogen 编排框架、Fara 计算机使用智能体，以及 Next Latent 目标、改进 Muon 的 Dion3、通过递归大幅提升模型能力的 Full Bandwidth Transformer 等基础性工作。今年 9 月初 AIF 被整体并入 Microsoft AI，而 MAI 由前 Inflection 班底主导，Langford 称其核心哲学是「规模优先、明确不做研究」，与 AIF 不兼容。他举例说，字节跳动的实验表明 Full Bandwidth Transformer 的某个变体可能相当于两倍大小的模型——在全行业投入接近一万亿美元的背景下，把训练和推理成本减半值多少钱？他拒绝回流 MSR，理由是「做出的研究没有通往实际使用的路径」，以及 MSR「做好工作就有好结果」这一基本契约已经破裂。AIF 创始领导层其他成员也都得出了类似结论。

**推荐理由**：一位顶级 ML 研究者对「规模化压倒研究」路线的公开控诉，罕见地从内部披露了微软 AI 重组的真实代价。

## [英格兰银行给 AI 生产力热潮泼冷水：三年只带来 0.5% 的生产力提升](https://www.theregister.com/ai-and-ml/2026/11/06/bank-of-england-pours-cold-water-on-ai-productivity-boom/5308059)

英格兰银行在最新《货币政策报告》中估算，过去三年 AI 给英国生产力带来的提升约为 0.5%——换算成年度增速，自 2024 年初以来仅额外贡献了 0.1 至 0.2 个百分点。报告措辞谨慎：「AI 投资似乎对当前需求强度有所贡献，但到目前为止只有证据表明 AI 驱动的英国生产力增长是温和的。」这与硅谷承诺的经济革命相去甚远。作为对照，同一窗口内 The Register 的另一篇报道指出，托管推理厂商 Fireworks AI 的 VP 正在劝阻客户自建私有 GPU 集群，理由是一万张 GPU 相当于十亿美元资本开支，利用率跑不满就是纯粹浪费。两条线索指向同一个问题：巨额资本开支与可测量的产出之间，仍然隔着一道没人填上的沟。

**推荐理由**：央行级别的独立测算，是对 AI 资本开支叙事最有分量的反驳之一，比任何分析师报告都难以忽视。

## [点一次「不再询问」，1122 个公开仓库里躺着真实密钥](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)

Apiiro 在 1994 个公开 GitHub 仓库中找到 2539 个真实可用的凭据：数据库口令、云密钥、API token、SSH root 登录信息，涉及 63 个组织，其中包括某数据库厂商自己的管理员级云密钥、一个生产环境 Azure Postgres 密码、一个 Square 生产 token，以及一个医疗记录数据库的所有者密码——已有一家组织确认其密钥处于活跃状态。成因很朴素：让 Claude Code 查一下数据库，它提出的命令会带上配置文件里的密钥；选「Yes, and don't ask again」，这条含密钥的完整命令就被写进项目目录下的 `.claude/settings.local.json`，而仓库里没有任何东西标记该文件为私有，于是随代码一起提交。该文件在 GitHub 上有 104185 份公开副本，1122 份含真实密钥；git 历史、团队共享的 `settings.json` 和存进仓库的智能体对话记录里还有 1160 个。其中五分之一连 gitleaks 和 TruffleHog 都扫不出来，因为密钥是命令行里手打的密码而非可识别格式的 key。

**推荐理由**：一个交互设计缺陷造成的大规模凭据泄露，所有用编码智能体的团队今天就该自查，且现成扫描器对五分之一的样本无效。

## [Anthropic 谈智能体记忆：让 Claude 在空闲时「做梦」来整理自己的记忆](https://www.anthropic.com/research/components-of-agent-memory)

Anthropic 发布了一篇关于智能体记忆设计的工程文章，核心类比来自神经科学：人类海马体在当下快速编码经验，但只有部分经验会在离线状态（睡眠与安静休息）通过回放被逐步蒸馏、整合进新皮层。智能体可以采用同样的分工——它们本就把大量工作留在日志和对话记录里，参照 Letta 与 UC Berkeley 提出的 sleep-time compute，模型可以利用交互间隙反思日志、修正错误、生成新笔记和新的记忆表示，这个过程被称为「做梦」（dreaming）。文章界定了「智能体记忆」的边界：指 Claude 从与用户和任务的交互中获得、并在会话之间保留下来的、可供日后读取的上下文知识，不包括权重更新、单次对话内的上下文学习，以及压缩（compaction）。文中还给出了用于探索各记忆组件贡献的若干评测。

**推荐理由**：长期运行智能体的记忆架构是当前最实际的瓶颈，这篇把脑科学类比落到了可评测的工程组件上。

## [苹果的「灰名单」：超过十万个词和短语，你的 iPhone 拒绝帮你拼写](https://www.theguardian.com/technology/2026/nov/06/struggling-to-spell-male-chauvinist-pig-apple-grey-list-means-your-iphone-wont-help-you)

独立研究者 Derik Kauffman 发现，苹果维护着一份超过十万条的「灰名单」，其中的词与短语被排除在预测文本补全之外。该限制主要作用于滑动输入（swipe-type，手指在键盘上划过而非逐字点按）：名单上的内容不会被补全，用户只能一个字母一个字母地敲出来。被挡住的不只是明显的脏话，还包括「male chauvinist pig」这类日常表达，以及涉及性取向、药物、情报机构等话题的组合。这意味着一层几乎不可见的内容策略被嵌进了最基础的输入法环节——它不阻止你发送任何内容，只是悄悄让某些表达变得更费力，而用户从未被告知这份名单的存在、范围或收录标准。

**推荐理由**：设备端 AI 的内容策略不经声明地影响日常输入，是「摩擦即审查」的典型样本，且影响面覆盖全部 iPhone 用户。

## [StrataFlux：把额外精度放进内存和 SSD，2-bit 模型的 AIME 准确率从 11% 拉到 47%](https://arxiv.org/abs/2611.08363)

康奈尔与 CMU 的工作针对低比特 LLM 推理的经典两难：量化省显存但掉精度，把高精度数据卸载到慢速存储又会卡住生成。StrataFlux 协同设计了精度补偿的表示、选择与投递三个环节，让主机 RAM 和 SSD 成为可用的额外精度来源——选择性精度流式传输减少传输量、让投递与计算重叠，并在多个解码步之间复用已取回的精度，使生成不必等待每一次传输。实测在 RTX 5090 上，2-bit Llama-3.1-8B-Instruct 的 WikiText-2 困惑度从 9.46 降到 8.40，同时保持量化基线 95.4% 的吞吐；2-bit 权重加 2-bit KV 的 Qwen3-8B 在 AIME 2024/2025 上的准确率从 11.0% 升至 47.1%，显存占用不变；128K 上下文下，3-bit 权重加 2-bit KV 可达到与 vLLM 的 4-bit AWQ + 8-bit KV 相当的困惑度和速度，显存约为其一半。

**推荐理由**：本窗口最扎实的小型化论文，重量级单位出品，把「显存里的精度就是精度上限」这一默认假设直接推翻。

## [libghostty 1.0 发布：JetBrains 全系 IDE 的终端已经跑在它上面，覆盖 1250 万用户](https://mitchellh.com/writing/libghostty-1-0)

Mitchell Hashimoto 宣布 libghostty-vt 1.0 发布，库本身与 C ABI 同时进入稳定状态，并有强制执行的 ABI 稳定性策略。这个从 Ghostty 核心中剥离出来的可移植高性能终端仿真 C 库，一年时间里已经渗透进整个行业：JetBrains 全系 IDE（IntelliJ、PyCharm、GoLand 等）的终端已经替换为 libghostty，据 JetBrains 报告覆盖超过 1250 万活跃用户；Neovim 有一个用 libghostty-vt 替换 libvterm 的 PR 已获批准，顺带关掉了一个关于 resize 时回滚缓冲区重排的十年老 issue，维护者正等这次发版以便发行版单独打包依赖；KDE 开发者在试验基于它的 Konsole 替代品；Vercel 的 Turborepo 用它渲染 TUI 输出；OrbStack 等商业产品内嵌了它。社区绑定覆盖 Rust、Go、JavaScript、Swift、Python、.NET、Elixir、Dart、Java 等。

**推荐理由**：把一个被反复重写了四十年的组件做成真正稳定的共享基础设施，且已在数千万用户规模上验证——基础库的正确做法。

## [31B 视频音频生成模型压到 13.7B、6 步出片，Q4 量化只要 9.1 GB](https://github.com/Video-Rebirth/hyperflow-h3-flash)

Video Rebirth 放出 HyperFlow H3 Flash，是 MiniMax-H3 的压缩少步版本，可联合生成视频与同步立体声音频。模型从约 31B 的 transformer 压到 13.7B（`fl2va`）或 13.9B（`ref2va`），不到原来的一半；采样支持 4、6（默认）、8 步，且不需要 classifier-free guidance。默认输出 1344×768、24fps 的 5.2 至 15 秒视频加 32kHz 立体声。速度方面，生成 5.2 秒片段 6 步，4 张 B200 需 8.7 秒、单张 H200 需 36 秒、单张 RTX 5090 需 92 秒；NVIDIA SOL-H3 可在 4 张 B 系列 GPU 上做到实时。最小占用是 `Q4_K_M` 的 9.1 GB，能在 24GB 和 32GB 显卡、16GB 系统内存的 PC 上跑起来。权重 Apache-2.0，提供 INT8 与 GGUF 两条路线，打通 ComfyUI、Unsloth Studio 和 stable-diffusion.cpp。

**推荐理由**：音视频联合生成下放到消费级单卡的一个清晰节点，压缩倍率、步数与量化方案全部公开可复现。

## [Turbo Pascal 7：集成源码级调试诞生的地方，以及它为什么再也没有了](https://kevinboone.me/tpwin.html)

Kevin Boone 回顾 Borland Turbo Pascal 7（即 Turbo Pascal for Windows 1.5）——Turbo Pascal 产品线的巅峰，也是它的终点。TP 引入了今天被视为理所当然、但在当时堪称激进的开发技术，首推集成的源码级调试。它的商业模式同样特别：「Turbo」这个名字对应被视为业余爱好者的产品线，价格低廉，而「Borland Pascal」是另一个昂贵得多的产品；TP 采用「书籍式授权」——买一份拷贝，任意多人可以使用，但同一时刻只能一人，即使在软盘分发年代也完全没有复制保护。作者当年用 TP 7 在 Windows 3.1 上写医学影像软件：那时用 C 为 Windows 编程是件痛苦的事，需要拼凑一整套以晦涩文本文件为输入的命令行工具，而 TP 7 把这些全部自动化并隐藏了起来；Windows 的界面模型本质上是面向对象的，而 TP 5 引入的对象概念加上 Object Windows Library 恰好接上了这一点。

**推荐理由**：IDE 这一形态在 1990 年代初就已基本成型，这篇从使用者视角讲清了它当年解决的具体痛苦，也讲清了「书籍式授权」这种已经消失的商业模式。
