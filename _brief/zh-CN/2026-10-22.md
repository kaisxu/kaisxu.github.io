## [PHP2Shell：前沿模型挖出潜伏十余年的 PHP 核心 RCE，波及全球 70% 网站](https://www.wiz.io/blog/php2shell-php-rce)

Wiz Research 披露 PHP 核心引擎中的两个严重漏洞（CVE-2026-109618 / 109619，CVSS 最高 9.2），分别源于内存分配触及 `memory_limit` 时留下半初始化结构、以及致命错误后内部状态指向上一请求已释放的内存。PHP 5.4 以来的每个版本都至少受其一影响；在 Apache + mod_php 默认配置下，未认证请求可在任何应用代码执行前就完成远程代码执行。PHP 承载了 WordPress、Drupal 与维基百科的 MediaWiki，官方已于 10 月 21 日发布 8.5.12、8.4.27、8.3.36、8.2.35 修补。PHP 基金会在[同日复盘](https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/)中坦承，OOM 问题早在 2024 年外部审计时就已露头，却因修复方案各有兼容性代价、小团队难以达成共识而反复停摆——"这是一次结构性失败"。

**推荐理由：** Wiz 自比 Heartbleed 与 Log4Shell。真正的转折点不是漏洞本身，而是"复杂度不再构成防护"——模型把人类难以完成的利用链压缩到了数小时。

## [PyPI 上的 LiteLLM 1.107.0 被投毒：凭据窃取器在任何 Python 进程启动时都会运行](https://safedep.io/litellm-pypi-compromise-credential-stealer-backdoor/)

LiteLLM 1.107.0 的全部七个 wheel（Linux/macOS/Windows）向 `site-packages` 植入三个文件。`cook.pth` 拉起凭据窃取器，收集 SSH 密钥、云凭据、CI/CD 机密、AI 工具令牌、浏览器密码以及 LiteLLM 代理数据库里的各家 LLM 供应商 API key，加密后外传至伪装域名；`sitecustomize.py` 则驻留后台守护进程，每小时从 GitHub 读取服务器地址并下载执行代码。两者在主机上**任何** Python 进程启动时都会加载，哪怕该进程从未 import litellm。上游 GitHub 仓库中不存在这些内容，恶意 sdist 仅多出 `data = "cook"` 一行；SafeDep 查遍 539 次 Actions 运行，没有任何公开流水线构建了该版本。PyPI 已下架。

**推荐理由：** 攻击面精准对准了 LLM 网关这个密钥汇聚点，且通过 `.pth` 实现了与业务无关的全局执行——这是供应链投毒向 AI 基础设施的一次升维。

## [GitHub 把最繁忙的仓库搬进 Azure：问题出在一次 25 毫秒的往返](https://github.blog/engineering/architecture-optimization/the-bridge-to-agent-scale-git-infrastructure/)

过去一年里，GitHub 上 99.99999% 的 Git 仓库已同时存在于自有数据中心与 Azure；剩下那万分之一是平台上最繁忙的仓库，被一件事卡住——1000 英里带来的 25 毫秒网络往返。迁移的时机与形态由智能体转向驱动：流量指数增长，而自有数据中心及所在地区的供电能力有硬上限、供应链也有物理约束，"剩余容量够我们安全迁移，但不够我们慢慢迁"。现行架构中 Spokes 的 quorum 虽只需多数即可提交，却要等待所有健康副本响应，于是最慢的副本决定了每一次写入的延迟，而写入持有仓库级锁，也就决定了吞吐天花板。解法是缩小 quorum 的作用域——Git 的一致性要求本就是按 reference 逐个成立的，互不依赖的引用更新没有理由被串行化。

**推荐理由：** 一句"够安全迁移但不够慢慢迁"道出了 AI 时代基础设施的真实约束：瓶颈已经从工程能力转移到了电力与供应链。

## [Lafa：连续流语言模型首次扩到 80 亿参数，吞吐是自回归基线的 2.54 倍](https://arxiv.org/abs/2610.28559)

来自 UC Berkeley、KAIST、CMU 与 Amazon 的团队提出 Lafa，把连续流（continuous flow）语言模型推到 8B 规模。它采用分块设计：前缀上走因果注意力，块内走双向、带左到右偏置的异步流，从而既能高效改造预训练自回归模型，又保留 prefix caching 与块内并行解码。全部 0.5B / 7B / 8B 三档模型的训练消耗不到 300 亿 token，而可比的离散扩散模型适配需要多达 5000 亿。关键发现是流训练非但不损害、反而通过多 token 预测效应增强了原有的自回归能力——于是同一个模型既能产出流式草稿，又能自回归地验证它，这套自推测解码在质量持平的前提下取得自回归基线 2.54 倍的吞吐，优于多 token 预测与离散扩散路线。

**推荐理由：** 扩散/流式 LLM 一直受困于"小规模能跑、放大就崩"。用预训练 AR 模型做底座改造而非从头训，可能是这条路线真正落地的那把钥匙。

## [DuckDB 2.0.0 LTS 发布："Cinnamon Teal" 积累了近两万次提交](https://duckdb.org/2026/10/21/announcing-duckdb-200)

自 1.5 以来累计近 20,000 次提交后，DuckDB 迎来迄今最大的功能版本。1.0 关乎稳定性与向后兼容，2.0 则是一次彻底的功能释放：打磨后的 Quack 协议让这个从第一天起就是进程内的数据库能以传统客户端-服务器方式运行，新增的 `CONNECT` 语句可一条命令完成挂载并切换到远程库，且不限于 Quack——PostgreSQL 与 MySQL 同样适用，配套的远程下推优化器会把查询直接送到远端而非把表拖过网线。此外还有异步 I/O、一等公民的 `VARIANT` 类型、agent mode、触发器与可扩展 SQL 解析器。该版本为 LTS，支持至少到 2027 年 10 月；1.5 的支持期也延长至 2027 年 3 月。

**推荐理由：** 一个以"嵌入式"为身份标签的数据库长出了服务端形态，却没丢掉单文件的轻便。本地分析与远端仓库之间的那堵墙正在变薄。

## [Google 公开其内部 Rust 风格指南：禁用 async/await，避开 Rc 与 Arc](https://google.github.io/styleguide/rustguide.html)

Google 将其 Rust 风格指南加入公开的 Google Style Guides 系列。除了"遵循公开 Rust 风格规则"的基线外，其中不少条款相当有立场：所有权与借用一节直接要求"避免使用 `Rc` 和 `Arc`"、优先借用而非深拷贝；API 设计上主张用 enum 取代 bool 参数、为重要的 `From` 实现配套显式构造方法、对外暴露的 enum 与含公开字段的 struct 加 `#[non_exhaustive]`。并发章节中标注 `[chrome]` 的条目尤为醒目——在 Chrome 代码库内不得使用 `async` / `.await`，也不得通过 Rust 标准库启动新线程。实现层面还有"优先 `expect` 而非 `unwrap`"、"不要过度依赖类型推导"、不得在 `main()` 之前运行代码等细则。

**推荐理由：** 在超大规模代码库里，Rust 语言层面"安全"的东西未必是工程上可维护的。这份指南的价值正在于标出了那条差异线。

## [CIA 如何给了 Steve Jobs 绝密权限：无标记卡车在清晨运走未完工的 NeXT 工作站](https://brianroemmele.substack.com/p/how-the-cia-gave-steve-jobs-a-top)

1986 年，CIA "Program B" 的两名人员未经预约走进 NeXT 总部。冷战仍在继续，情报机构需要更强的机器把卫星照片转化为国家侦察局可用的情报。彼时 Jobs 刚离开苹果一年，创办 NeXT 并买下 Lucasfilm 图形部门（即后来的皮克斯）。对方开口要两万台，附带两处改动：更快的摩托罗拉芯片与一块特制的 Intel 图形卡——NeXT 不做改装，由机构事后通过中间方完成。采购记录挂在国家安全局名下，对外只说是经 ESL 承接的联邦合同。机器未完工即出厂，无标记卡车清晨从仓库取走送往 CIA 的空壳公司，装好芯片后运至 Moffett Field 由 C-5 飞往机密目的地，月产量从约一百台爬升到五千台。Jobs 本人随后获得 Top Secret SCI 权限。

**推荐理由：** 硅谷与情报机构的早期纠缠向来被传说包裹。这篇把时间、型号、运输路径和解密文件一一对上，读起来像一份冷战硬件史的注脚。
