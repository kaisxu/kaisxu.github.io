## [Claude Fable 5.2 与 Mythos 5.2 发布：1000 个智能体 30 小时形式化了费马大定理](https://www.anthropic.com/claude-fable-and-mythos-5-2)

Anthropic 于 11-09 发布 Fable 5.2 / Mythos 5.2——两者是同一底座模型，Mythos 去掉了网络安全与生物学的防护限制，仅向通过审核的生命科学与网络安全验证项目开放。官方称在预发布测试中，模型完成了「不可行」的软件迁移、从零设计出三款可工作的电子设备、解决了黑洞物理学的两个开放问题。最受关注的数字是：一个由 1000 个 Fable 5.2 智能体组成的团队在 30 小时内、几乎无人工干预地完整形式化了费马大定理，而此前一个未发布的研究版本借助专用脚手架加人类研究者指导耗时 11 天。定价降至每百万输入 token 8 美元、输出 40 美元，生成速度比 5.1 快 30%，另有 2.5 倍加速的 fast 模式（16/80 美元）。FrontierCode 2.0 得分 49.1%（Opus 5.5 为 45.5%），Artificial Analysis 综合指数 65 分创历史新高。

**推荐理由**：前沿模型能力的又一次跳变，而且「降价同时提速」打破了旗舰模型越强越贵的惯例。HN 上 481 条评论里一半在追问 5.5 是否为发布预热而被降智。

## [C++26 标准投票失败：语言创造者与语言所有者公开分歧](https://isocpp.org/files/papers/P4454R0.pdf)

Herb Sutter 的 P4454R0 提案文件记录了一桩 36 年来首次发生的事：C++26 的国际标准投票没有通过，而主要推力被归结为 Bjarne Stroustrup 对 contracts（契约）特性的公开反对——他另撰《Contracts: fundamental flaws》列举了一组设计缺陷。Sutter 在文中列出六条可能的出路，从「跳过 C++26、把特性并入 C++29」「移除 contracts 后重新投票」，一直到最激进的「以各国国家标准而非国际标准发布」乃至「离开 ISO 转向 ANSI」。HN 153 条讨论里有相当一部分认为 Sutter 低估了背景：社区对 modules 这类「半成品大特性丢给实现者」的疲惫感早已积累。

**推荐理由**：一门支撑了整个基础设施层的语言，其治理机制第一次在公开场合卡死，六条出路里有两条涉及脱离 ISO。

## [Meta 发布 Muse Ember：最小模型打到每美元智能的效率前沿](https://research.meta.ai/blog/muse-ember)

Meta 11-09 推出 Muse Ember，定位是专门承接智能体整日重复的那类活——工具调用、编码子任务、路由、抽取、长文档解析。官方数据称它在任意推理档位上的每美元智能都优于 Claude Haiku 5.5 与 GPT-6 Luna：以约三分之一的成本追平 Haiku 的最好成绩，并在 Artificial Analysis 完整榜单上落在效率前沿（没有模型能以更低的每任务成本拿到更高分）。定价每百万输入 token 0.10 美元、输出 0.50 美元，缓存输入仅为输入价的 4%（Luna/Haiku 为 10%）。AutomationBench-AA 得 37.8（Haiku 13.9、Luna 20.2），Terminal-Bench 4.0 得 40.9。HN 上最集中的失望是：叫「最小模型」却没有开放权重，参数量也未公布。

**推荐理由**：大模型小型化这条线上的重要坐标——把「单位成本的智能」而非绝对能力作为发布的主轴来讲，这是一个取向上的转变。

## [Git 项目考虑用投票来决定自己的 LLM 政策](https://lwn.net/Articles/1104195/)

LWN 11-09 报道，Git 项目正在考虑引入一套投票流程，用来给「LLM 写的贡献该以什么条件接受、乃至是否应当接受」这个问题收尾。这个话题在最近的 Git Contributor's Summit 上被讨论过。值得注意的是路径本身的曲折：Git 从来不是以民主方式治理的项目，现在却准备为了结束这场争论而专门引入投票机制。LWN 把它放在 2026 年贯穿全年的主题之下——各个开发项目都在争论同一件事，而解决方式各不相同。同一天 The Register 报道 Linus Torvalds 认为内核的「AI 补丁洪水」最糟糕的阶段可能已经过去：Linux 7.4-rc2 中修复到达的速度已快于新漏洞报告的速度。

**推荐理由**：开源治理面对 LLM 的制度性应对，Git 这种「为了解决一个技术争议而改变治理形态」的做法会被其他项目参照。

## [两名研究者攻破车企 Android 应用，可远程解锁、启动澳美两国的任意车辆](https://shubs.io/unlocking-any-car-from-x-brand-in-most-of-the-world/)

Assetnote 联合创始人 Shubham Shah 与研究者 Sam Curry 今年合作拆解了某大型车企的车联网平台。路径完全走的是 Web 侧而非硬件侧：反编译 APK 重建 API 请求，在 JavaScript bundle 里找到硬编码的 API key 和一个权限过宽的内部管理工具，再配合从测试环境捞到的 ForgeRock OpenIDM 默认管理员凭据——这些凭据在生产环境同样有效。车企在 `/openidm/*` 敏感接口前堆了大量 WAF 规则，但两人绕了过去。最终形成的攻击链是：车牌号 → VIN → 订阅者 GUID → 车主账户 PII，进而向任意车辆下发启动引擎、闪灯、鸣笛、解锁等指令。Shah 表示针对美国的那条路径「工作量大得多」，因为该车企在美加欧的 OpenIDM 环境上投入了明显更多的加固。

**推荐理由**：车联网安全的典型失效模式——车端再硬，后台身份平台的一个默认口令就让整条链归零；而且受影响的是两个国家的在售车型。

## [DeepX 流片第二代 AI 加速器：5W 功耗跑 1000 亿参数模型](https://www.eetimes.com/deepx-tapes-out-second-gen-chip-projects-6-7x-performance-gain-with-lpddr5x-pim/)

韩国 DeepX 11-09 宣布第二代 NPU DX-M2 流片，目标是把生成式 AI 推到机器人、无人机这类功耗与散热都紧张的边缘设备上。规格是在同样 5W 功耗预算内跑 200 亿到 1000 亿参数的模型（活跃参数约 30 亿到 200 亿），速度 10–30 tok/s。内存带宽从 50 GB/s 提到 150 GB/s，NPU 能效靠设计改进翻倍、靠 2nm 工艺再翻倍，算力达 80 TOPS。更关键的是与三星定制 LPDDR5x-PIM（存内计算）的整合：把 GEMV 这类内存瓶颈算子下放到内存芯片内部执行，模拟显示 Llama3.1-8B 的 tok/s 可达 DX-M2 单独运行的 6.7 倍，代价是整体功耗增至 2.7 倍。下一代 DX-M3 将支持正式进入 JEDEC 标准的 LPDDR6 PIM。

**推荐理由**：存内计算从论文走到流片硅片，而且落在「边缘设备跑百亿参数」这个具体场景上——如果数字成立，本地化大模型的功耗门槛会被改写。

## [同一块 H100，租金在 2.69 到 12.29 美元每小时之间：4.57 倍价差](https://github.com/datareceipts/data-receipts/tree/main/109-gpu-pricing)

data-receipts 项目把 AWS、Azure 与各家 neocloud 的按需 GPU 租赁价格归一化为「每 GPU 每小时美元」，并严格按（型号, 显存）分组比较。结果是同一款 H100 SXM 80GB：RunPod Community 2.69 美元/小时，RunPod Secure 3.99，AWS p5.48xlarge 6.88，Azure ND96isr_H100_v5 12.29——最贵是最便宜的 4.57 倍。换算成一块卡连续跑一个月（730 小时），区间是 1964 美元到 8972 美元。作者特意强调了方法论上的克制：H100 其实是 SXM 80GB、PCIe 80GB、NVL 94GB 三种不同产品，混在一张表里会制造出不存在的价差；同一厂商内部也要分组，Azure 同一款 A100 PCIe 80GB 在 1/2/4 卡配置下就是三个价。

**推荐理由**：AI infra 成本侧少见的、方法论干净的公开数据，对判断算力定价与各家云的真实溢价很有参照价值。

## [Meta FAIR 开源 e-means：k-means 的现代化重写，十分之一的 epoch 数](https://e-means.github.io/)

Meta FAIR 的 Swann Bessa 等人（合作者包括 Hugo Touvron、Matthijs Douze、Hervé Jégou）开源了 e-means，用来替代 1957 年的 Lloyd 算法。做法是把现代深度学习的优化工具搬到 k-means 上：小批量更新 + 指数移动平均，并建立了衰减率与批大小如何影响最终性能的 scaling law，从而给出一条公式化的超参数设定规则，不需要任何 sweep。效果是 Lloyd 跑 25 epoch 达到的测试损失，e-means 用 1.2 到 3 个 epoch 就能跑到更低；端到端测算，GPU 上相对最优 Lloyd 实现（Flash-KMeans）快 10–45 倍，CPU 上相对 Faiss 快 8–15 倍。代码已并入 faiss（`faiss/contrib/e_means`）。论文见 arXiv:2611.09501。

**推荐理由**：聚类是量化、检索、数据筛选的底层组件，一个被用了近七十年的默认算法被整体换掉，影响面会比表面上看起来宽。本条为本期论文条目之一。

## [Outlook.com 开始拒收无 DMARC 记录的域名邮件，且已误伤合法邮件](https://www.theregister.com/applications/2026/11/09/outlookcom-bounces-legit-emails-as-microsofts-authentication-crackdown-goes-sideways/5308428)

自 11 月 5 日起，微软的消费级邮件服务（outlook.com、hotmail.com、live.com、msn.com）开始退回部分来自未发布 DMARC 记录域名的邮件。The Register 11-09 报道，这次收紧出了岔子：一个校验错误导致 Outlook.com 连合法邮件也一并拒收，受影响用户收到的退信错误码既有 SPF 校验失败的，也有提示缺少 DMARC 信息的。问题从上周末开始出现，范围看上去相当广。对企业来说，直接后果是发给使用微软消费邮箱的客户、供应商、求职者的邮件可能静默失败。MailRoute 11-06 的技术分析是这件事最早的公开记录，在 HN 拿到 527 分。

**推荐理由**：邮件认证这类「大家都知道该做但一直拖着」的基础设施债，被一家占据巨大收件端份额的厂商单方面强制清算，而且清算过程本身还出了 bug。

## [在自己的 VM/370 CE 上找点乐子：Docker 一行命令起一台 1970 年代的大型机](https://rbanffy.github.io/fun-with-big-computers/fun-with-vm370/)

一份面向 VM/370 Community Edition 的实操指南。VM/370 R6 是 IBM 在无使用许可限制条件下发布的最后一版，CE 则是社区在其上数十年积累的修复与增强的集合——作者打的比方是：R6 相当于 Linus 在卧室里发布的 Linux 1.0，CE 相当于今天的 Fedora，尽管它跑的机器仍限于单 CPU 和 16MB「storage」。入门门槛低到一条命令：`docker run -it --name vm370 -p 3270:3270 rbanffy/vm370ce`，终端上直接显示机器控制台。文中也认真讨论了另外两条路——说服公司运维在真 IBM 主机上开一个嵌套 VM（技术上没问题，流程上很难，作者自陈试过且结局不佳），或者在 eBay 上买一台二手主机（需要专用供电线路）。

**推荐理由**：1970 年代分时系统的完整运行环境，今天用一条 docker 命令就能拿到手；CE 这种「社区在三十年里持续修一套公共领域操作系统」的存在本身也值得一看。
