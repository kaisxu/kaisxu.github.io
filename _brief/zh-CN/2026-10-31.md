## [AI 写出的内核漏洞利用已落地：CVSS 9.8 的 TCP 竞态横扫 Go 服务](https://lwn.net/Articles/1104192/)

Anthropic 10 月 27 日披露 CVE-2026-98432：Linux IPv4 在处理重传 SYN 与另一线程建立连接之间存在竞态，`ireq_opt` 在仍被引用时就被 `kfree()`，造成可远程触发的 use-after-free，可泄露内核内存或写入攻击者控制的载荷。内核 CVE 团队给 9.8 分，Anthropic 称其模型自行写出了无凭证取 root 的利用。真正的放大器是 Go：自 1.24 起 Go 程序监听套接字默认启用 multipath TCP，意味着 Kubernetes 等大量 Go 服务在无人知晓的情况下暴露在外。修复是改用 `kfree_rcu()`。截至 10 月 29 日 Debian、SUSE、Amazon Linux 已发包，Ubuntu 与 RHEL 尚未。

**推荐理由**：第一次有大厂公开承认「模型写出了内核 0day 利用」并同时命中一个默认开启的语言运行时特性，攻防节奏的变化比漏洞本身更值得警惕。

## [官方 Claude Code 扩展被植入 SSH 后门，Anthropic 否认自身被攻破](https://phorion.io/blog/offical-claude-code-vsx-compromise/)

EDR 厂商 Phorion 在 Cursor Marketplace 上的 Claude Code for VS Code 2.1.313 版本中发现持久化 SSH 后门，覆盖 macOS、Linux、Windows 三平台，约 5000 名开发者受影响。扩展以 IDE 权限加载，一旦载入即可触及本地文件、源码和开发工具链。有趣的是 macOS 上植入逻辑有 bug：非 root 执行 `systemsetup -getremotelogin` 会打印权限错误并以状态 0 退出，脚本因只在输出为 `Off` 时才启用 SSH 而跳过了这一步——密钥和持久化照样落盘，入站通道却没打通。Cursor 已下架该版本并撤回对应 NPM 与 VSCode 包。

**推荐理由**：AI 编码工具正在成为供应链攻击的新上游；而「官方扩展」的信任边界究竟归谁所有，这次事故给出了一个尴尬答案。

## [Postgres 19 延期，Robert Haas 把原因归给 LLM](https://lwn.net/Articles/1104210/)

PostgreSQL 核心开发者 Robert Haas 撰文解释 19 版延期：延期本身源于项目对质量的坚持，在大局上并不算长。更麻烦的是长期图景——他写道「我们有四十年来人类未能发现、而 LLM 相当擅长挖出的 bug，我们要怎么追上这个进度，PostgreSQL 又要如何继续创新？」言下之意是模型辅助审计一次性翻出的历史缺陷存量，超过了项目既有的修复吞吐。LWN 评论区的主流反应是：数据库稳定性压倒功能数量，少发点新特性换高质量是划算买卖，且 LLM 同样可以用来修 bug 和补测试。

**推荐理由**：这是「LLM 找 bug 能力溢出」第一次具体压垮一个四十年老项目的发布节奏，比任何 benchmark 都更能说明代码审计的格局变了。

## [一颗 NES 的 CPU 被编译进 Qwen3.5 的权重里](https://github.com/dbreunig/nesformer)

nesformer 把 NES 的 6502 CPU 核心、2KB 工作 RAM 和卡带 ROM 全部编译成一个标准 `Qwen3_5ForCausalLM` 检查点的权重——没有任何训练，每个数值都由编译器算出。玩游戏时模型逐 token 预测 CPU 执行日志，宿主程序负责画面、手柄输入和 vblank 中断。项目建立在 Divyansh Agrawal 的 Qwenputer（曾把 CHIP-8 与 RISC-V 编译进 Qwen3.5-4B）之上，复用了其核心技巧：把模型的 Gated DeltaNet 状态当作机器的内存。作者验证了《超级马里奥兄弟》World 1-1 等测试 ROM 的每一帧都与常规 6502 模拟器逐像素一致。

**推荐理由**：既是复古计算的恶趣味，也是对「Transformer 状态等价于什么计算模型」最具体的一次演示——逐帧比特精确，没给含糊留余地。

## [把经典 Mac OS 移植到 Nintendo Wii，全程未用 AI](https://virtuallyfun.com/2026/10/29/my-favourite-powermac-is-a-nintendo-wii/)

开发者 Rairii 宣布 Mac OS 7.6 与 9.2.2 已在 Wii 上启动到桌面，很可能是 CHRP 克隆机时代之后首次有 Apple 之外的人把经典 Mac OS 带上全新硬件。路径是看中 GameCube/Wii/Wii U 共享的 ArtX 系芯片组血统（Flipper、Vegas/Bollywood、Latte 一脉相承），先移植 OpenBIOS 以支撑「New World」Mac OS 的 Trampoline 引导器，复用 Goldfish64 的 Wii OpenBIOS 显示驱动，再把自己此前的 NT ARC 固件加载器改为加载大端 ELF。作者特别注明：项目始于 2025-06-22，全部编码、逆向与调试由本人完成，未使用任何编码智能体或 LLM，「用了 AI 就不好玩，也学不到东西」。

## [Tokio 作者推出 Topcoat：让 Rust 做服务端渲染的 Web 框架](https://www.theregister.com/devops/2026/10/29/topcoat-enables-rust-to-render-server-side-web-apps/5306470)

AWS 首席工程师、Tokio 作者 Carl Lerche 在 ScyllaDB P99 2026 大会上演示了 Topcoat——一个用 Rust 写 Web 应用的框架。与 Leptos、Dioxus 把 Rust 编译成 WebAssembly 送进浏览器不同，Topcoat 走服务端渲染路线，绕开 WASM 包的首屏加载代价，同时保留 Rust 的运行时性能与安全保证。Lerche 的论点是：三年前说「Rust 可能是写 Web 应用最好的语言」会被当成疯话，但 AI 承担了样板代码的重活之后，语言选择的权重正在从「团队熟悉度」转回「运行时特性」。

**推荐理由**：Rust 在 Web 层一直缺一个不依赖 WASM 的答案；由 Tokio 作者亲自下场，这个尝试的生态影响力值得跟踪。

## [苹果用在线 RL 训练 iOS UI 智能体：8B 模型打平 Gemini-3.1-Pro](https://arxiv.org/abs/2610.39264)

苹果提出在真实 iOS 应用上做在线强化学习的 UI 导航框架，针对的问题是：前沿视觉语言模型推理成本高到无法日常使用，而小模型靠 SFT 或离线 RL 往往只是背下静态轨迹，执行脆弱且无法从错误中恢复。方法上把智能体拆成 Planning 与 UI Grounding 两部分，用 LLM-as-a-Judge 同时给出步骤级稠密反馈与任务级终局奖励，再用带步骤级优势估计的 PPO 优化；并提出 GiGPPO，借并发轨迹中视觉相似状态的奖励信号来稳定 critic。基础设施层面调度数百台并发 iOS 虚拟设备。8B 智能体在跨到 Android 的分布外泛化上较 SFT 基线提升近七倍，真实 iOS 任务上超过 Gemini-3.5-Flash、与 Gemini-3.1-Pro 打平。

**推荐理由**：小模型靠在线 RL 追平前沿大模型的具体证据，且训练环境是真机而非模拟器——这是大模型小型化与定制化方向上信息量最高的一篇。
