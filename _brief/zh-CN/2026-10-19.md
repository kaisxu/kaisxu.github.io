## [Anthropic 游说的 AI 安全法案：只有 50 人死亡或 10 亿美元损失才触发，且只有商务部能叫停模型](https://www.tomshardware.com/tech-industry/artificial-intelligence/anthropics-proposed-ai-safety-bill-only-kicks-in-if-50-deaths-or-usd1-billion-in-damages-are-on-the-line-proposal-would-effectively-make-the-commerce-department-the-only-agency-capable-of-stopping-an-ai-model)

据 Politico 报道，Anthropic 正在低调推动一份联邦 AI 安全法案，其门槛设得相当高：只有当模型可能造成 10 亿美元损失、或致死致伤 50 人以上时，政府才可阻止其发布。风险来源限定为三类——生物武器、AI 驱动的网络攻击、以及实验室对模型或智能体失去控制。机制上由一家在商务部注册的独立第三方定期评估实验室及其模型（实验室可以付费给评估方，前提是不影响其独立性），发现风险须 72 小时内上报，商务部再把证据提交华盛顿特区联邦地区法院，由法官裁定是否暂停发布。法案还明确写入：除商务部外，美国任何其他部门、机构或官员都无权命令实验室停止发布模型。Anthropic 发言人称这是其 6 月起就在推动的 Advanced AI Framework 的立法化。

**推荐理由**：一家前沿实验室亲手为监管自己划定触发线，并把其他所有监管者挡在门外——这是产业俘获监管的教科书式动作。

## [DeepSeek 把自研搜索引擎开成 API：每千次请求 0.75 美元，11 月 1 日起对 Claude Code 等 harness 开始计费](https://api-docs.deepseek.com/guides/search/)

DeepSeek 上线 Search 与 Fetch 两个原始 JSON API，由其**自研搜索引擎**驱动，与模型 API 共用 bearer 鉴权。Search 接受 1–128 字符查询，支持 `site:`、`-site:`、`lang:`、`after:`/`before:` 等运算符，返回最多 50 条结果，每条带 `rerank_score`（0–3，≥1.5 为高质量）、600–800 字的模型可读 `summary`、以及 `authority` 权威度分级（0–4）；`need_content=true` 时直接返回正文。Fetch 则把单个网页转成 Markdown。计费按**成功请求数**而非 token 或结果条数——每千次 0.75 美元，空结果、超时和失败请求不计费，`count` 调大不涨价。文档末尾一句话值得注意：通过 DeepSeek Harness、**Claude Code 或 Codex** 调用 DeepSeek API 时，服务端工具调用已经在打这两个 API，目前免费，**北京时间 2026 年 11 月 1 日 0 点起开始按次收费**。

**推荐理由**：一家模型厂商自建并商业化搜索索引，意味着 agent 的"看世界"这一层开始脱离 Google/Bing，定价也从 token 制转向请求制。

## [网站正在对 AI 智能体关门：Delta、摩根大通、嘉信理财、Yelp 陆续封锁](https://www.theverge.com/ai-artificial-intelligence/1013195/ai-agents-blocked-web)

OpenAI、Meta、Google 都在推销能替你订餐、清邮箱、买鞋的自主智能体，但互联网另一端正在关门。近几周 Meta Muse、xAI Grok、OpenAI Dots、Instinct 的用户陆续报告智能体在主流网站上被拦截：Yelp 向 TechCrunch 确认只放行付费接入其数据授权计划的智能体；达美航空禁止智能体代订机票；摩根大通和嘉信理财均以安全顾虑为由封锁智能体访问账户；Cars.com 和 Amtrak 等此前可用的站点也开始失效，暗示还有更多公司在悄悄封禁。这并非新冲突——亚马逊去年已封杀 Perplexity 的智能体购物功能并提起诉讼，称第三方代客下单"应当公开运作并尊重服务商是否参与的决定"；Perplexity 则反击说亚马逊真正在意的是智能体不看广告。

**推荐理由**：智能体的能力上限正越来越多地由对方网站的意愿而非模型本身决定，而拦截的理由恰好是广告与数据授权这两件商业模式的根。

## [vLLM 用编码智能体重写 Kimi K3 解码路径：GB300 上单层 23 个 kernel 压到 13 个，但审查跟不上了](https://vllm.ai/blog/2026-10-16-kimi-k3-megakernel)

NVIDIA 的 Benjamin Chislett 在 vLLM 博客详述了如何用**智能体辅助开发**为 Kimi K3 在 GB300 上构建统一的 CuTe DSL 解码路径，覆盖注意力、MoE 与 8/16 卡间通信。手段包括按 batch 选择不同 kernel 形状、把注意力输出投影直接与 all-reduce 和残差计算融合（走 NVLink 缓冲区、无栅栏交换）、拆分 MoE 路由计算到各 TP rank、以及在通信空窗期用侧流预取下一步权重进缓存。结果是单层从 stock vLLM 的 130 微秒 / 23 个 kernel 降到 69 微秒 / 13 个，16 卡 GB300 上 batch 1 配合 DSpark 投机解码达 840+ tokens/s，多种配置下解码吞吐提升 1.5–2 倍，AgentX 负载 P90 交互性最高提升 1.8 倍。但文章真正的重点是第二部分的坦白：**"智能体优化的推理代码正在超出我们的审查与维护流程"**——逐行理解每个 kernel、测试每种配置的人工流程太慢，省掉又会把 bug 放进生产，因此必须改为"隔离改动、限定支持范围、系统化自动验证、让贡献者自己跑评测"的新组织方式。

**推荐理由**：和内核、PostgreSQL 的情况同源——AI 生成代码的速度已经压垮人工审查，而这次是基础设施维护者主动重构治理流程而非抱怨。

## [陶哲轩博客客座文章：数学的黄金时代还是黑暗时代，取决于 LLM 的证明能不能被人读懂](https://terrytao.wordpress.com/2026/10/18/will-it-be-a-golden-age-or-a-dark-age-for-mathematics-and-science/)

德州大学的 Francesco Maggi 在陶哲轩博客上发表长文，提出一个具体而非抽象的忧虑。他指出 LLM 最擅长在 Lean 里写证明，而对真正重要的难题，这些 Lean 证明长达**数十万行**；并且出现了一个新趋势——**Lean 证明越长，其机器生成的自然语言"翻译"就越混乱、越不忠实**，原因尚不清楚。于是对最重要的问题，我们能得到正确但读不懂的形式化证明，和复杂到需要数学家花大量时间研读才能转化为人类理解的自然语言版本。由此导出核心问题："在没有人类理解的情况下，我们为什么还关心研究数学、甚至获得证明，除了给 LLM 刷榜？"他的"黑暗时代"不是产出下降——短期产出会壮观地增长——而是独立的人类科研活动逐渐萎缩，新知识的生产集中到少数几只手里，而这些手越来越无法理解自己产出的东西。他还指出 OpenAI 10 月 6 日那次发布中提到"试了 4000 个问题、成功了数百个"，那批失败的问题反而更值得公开研究。文末呼吁社会需要**更多而非更少**数学家。

**推荐理由**：把 AI 对科学的冲击从"会不会取代研究者"精确到"知识会不会变得对人类不可理解"，并给出了一个可检验的征兆：形式化证明到自然语言的翻译质量。

## [Stanford + Together AI：让智能体在潜空间里思考、用文本行动，token 省一半还提速 2.6 倍](https://arxiv.org/abs/2610.18861)

Stanford、Together AI、UIUC 与 Meta 的团队（James Zou 组）提出 HybridAgent，试图弥合两条互不相通的路线：文本智能体能调工具但每一步推理都要解码成 token，潜空间推理高效却**既没有原生的工具调用通路、也不可审计**。方案核心是 HybridLink——一个轻量残差适配器，把最后一层隐状态映射回输入嵌入空间，使模型能在单次生成中自由进出潜空间模式；连续工作记忆则无损保留跨轮次的混合上下文（文本 + 潜向量 + 工具返回）。配套的后训练分两步：HybridSFT 让主干模型学会与 HybridLink 协同，HybridRL 再学习**何时该在潜空间思考、何时该用文本行动**。在 Qwen3-Base 的 4B/8B/14B 三个规模、11 个基准（数学、科学、医学、检索、智能体推理）上，相比 GRPO、ARPO 等文本基线与 Coconut、SoftCoT 等潜空间基线平均提升 10.4%，同时 token 用量降低 35.5%–54.7%、推理加速 1.8–2.6 倍、成本降低 2.7–3.7 倍。作者称一个意外发现是潜空间里的"想法"可以渲染成人类可读的伪文本，因此并非黑箱。

**推荐理由**：潜空间推理此前最大的两个阻碍——不能调工具、不可审计——同时被绕过，而代价是省钱提速，这个组合很难不被跟进。

## [Ken Shirriff 开盖 Intel 8087：1980 年那颗把浮点加法提速近 100 倍的协处理器，微码逐条拆解](https://www.righto.com/2026/10/8087-addition-subtraction-microcode.html)

Ken Shirriff 用凿子撬开 8087 的封装，在显微镜下拍出高分辨率芯片图，逐条分析其微码与电路，讲清楚浮点加减法在硅片上究竟是怎么做的。8087 于 1980 年随 IBM PC 进入市场，相比 8086 把加法提速了近 **100 倍**，复杂运算提速更多。芯片中央的大矩形是微码 ROM，存放控制整颗芯片的 1648 条微指令；下半部分是对 80 位值做浮点计算的数据通路。数据通路里的关键部件是中央的整数加法器——一个操作数来自 B 寄存器，另一个来自临时寄存器或栈寄存器，结果存入 sum 寄存器。占据大量硅片面积的是移位器，因为它的电路要支持任意位数的快速移位，而浮点运算极度依赖移位来对齐操作数；旁边的前导零电路负责数出左侧有多少个零位或零字节以便移走。指数转换器则处理指数并检测上溢下溢。文章还覆盖了无穷大等特殊值的大量边界情况处理。

**推荐理由**：IEEE 754 的很多设计选择今天还在每颗 CPU 里，而这篇是少有的把标准的措辞还原成具体晶体管布局的文章。

## [一台桌面 3D 打印机打到了微米级：RepRapMicron 打出 0.5 毫米的 Benchy，材料全是常见件](https://github.com/VikOlliver/RepRapMicron/wiki)

μRepRap 的目标是做一台能做**微米（1 微米，即千分之一毫米）乃至亚微米加工**的 RepRap 自复制 3D 打印机，且只用常见、易获取的材料制造。这一精度最初建立在 OpenFlexure 项目设计的 3D 打印显微镜平台之上（项目后来发展出更适合原型制作与加工的变体，但仍向其致敬）。初代原型的预期指标是：在 10 毫米见方的工作区内实现优于 3 微米的可重复定位，并做出一个可在普通家庭工坊制造的探针尖端来替代打印头。项目称这个目标已基本达成，wiki 首页展示了用 μRepRap 打出的 0.5 毫米「Benchy」测试模型。整个项目以 wiki 形式开放，近期仍在活跃更新（10 月 13 日第 37 次修订）。

**推荐理由**：微纳加工长期被几十万美元的设备垄断，而 RepRap 当年正是用自复制和开源把注塑件制造拉下神坛——同一套方法论再来一次。

## [OpenBSD 新增 uncm(4) 驱动：安卓 USB 共享网络终于能用，而且不需要固件 blob](https://www.undeadly.org/cgi?action=article;sid=20261018200218)

Jan Schreiber 向 OpenBSD 的 tech@ 邮件列表提交了一个 USB network control mode 驱动 uncm(4)。起因很朴素：Android 6 之后的设备 USB 共享网络不再走 urndis(4) 而改用 CDC NCM，而 OpenBSD 缺这个驱动。他顺手把一些宏和结构体从 mbim.h 挪到 usbcdc.h，以免为了移动宽带把整套东西都 include 进来（对 umb(4) 无功能性改动）。经过一轮往返讨论，stsp@ 第二天就把驱动合入主线。真正的收益在于这个驱动**不需要任何固件 blob**——于是它解决了一个长期的鸡生蛋问题：新笔记本的无线网卡需要固件才能联网，而固件又得联网才能下载。因此 Stefan 进一步把它放进了 amd64 的安装内核，用户现在可以用安卓手机 USB 共享网络来完成安装。赶在即将发布的 8.0 版本前刚好来得及。

**推荐理由**：一个两天内从邮件列表走到安装镜像的驱动，顺手拆掉了 OpenBSD 装机最恼人的死锁，也是"拒绝 blob"这条路线少见的正收益案例。
