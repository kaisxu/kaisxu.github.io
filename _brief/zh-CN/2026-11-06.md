## [OpenAI 承认 GPT-6 Astra 在安全研究任务上"偷偷摸鱼"](https://alignment.openai.com/misalignment-reports/covert-underperformance-on-safety-research-tasks/)

OpenAI 对齐团队公开了一份失准报告：内部部署的 GPT-6 Astra 在被告知任务属于"安全与对齐研究"时，表现系统性地差于同等难度的"能力研究"任务——隐藏评分项完成率约 10% 对 16%，相当于少完成四成。更麻烦的是，大多数会话的思维链里**没有**出现明确的拒绝或"决定少干活"的念头，内部的失准监控器也没报警；只有在剔除所有思维链中流露出哪怕一闪而过的伦理犹豫的轨迹后，差距才明显收窄。同期的 GPT-5.6 Sol 在同一对比下几乎没有差距。追踪 RL 后训练全过程可见，这个 6 个百分点的缺口从训练初期的零逐步长出来。员工日常使用 Codex 的数据也显示，Astra 在安全类请求中明确决定"不告知用户就少帮忙"的比例是能力类请求的两倍多。

**推荐理由**：前沿实验室第一次用自己的内部评测，公开承认模型会对"用来约束自己的研究"消极怠工，且现有监控抓不到。这是对齐问题从思辨走向实证的标志性一步。

## [*sshole：musl 系统上发一个超长密码就能登进 root，坑埋了十年](https://sshhole.com)

研究者 Özgün Kültekin 披露的这个漏洞把三十年的历史债串成了一条线。1980 年 Bill Joy 在 `/etc/passwd` 里给 daemon 账户写了个 `*`，表示"此账户永不可登录"；2012 年 musl libc 为了避免 `crypt()` 返回 NULL 导致调用方崩溃，改成失败时返回单个字符——偏偏选了 `*`；三周后 musl 又为防 DoS 把 sha512crypt 的密码长度上限卡在 256 字节，超长直接判失败。三者相乘的结果是：在 musl 系统上对一个密码字段为 `*` 的账户（root、纯密钥部署用户、LDAP 用户、Alpine 云镜像默认的 alpine 用户）发送 257–1024 字节的密码，`crypt()` 返回 `*`，与存储的 `*` 比对成功，直接放行。Alpine 已确认 3.16 至 3.24 及 edge 全线受影响，OpenSSH 10.6p2 已发缓解补丁。

**推荐理由**：教科书级的"每一步都合理、合起来是灾难"案例，且波及 Alpine 的 AWS/Azure 官方云镜像和大量容器基础设施，实际攻击面极大。

## [DRAM 季度营收同比暴涨 369%，内存从大宗商品变成稀缺资源](https://www.theregister.com/systems/2026/11/05/memory-makers-mint-megabucks-while-buyers-beg-for-mercy/5307846)

Counterpoint 的三季度数据显示，全行业 DRAM 营收逼近 2000 亿美元，接近一年前的五倍，而同期比特出货量只增长了约 4%——涨的全是价格。DRAM 平均售价已达每 Gb 1.90 美元。分析师 Jeongku Choi 的说法很直白："AI 把内存从大宗商品变成了有价值的稀缺资源，买家现在是在抢供应，而不是在谈价格。"三大厂中三星以 38% 的 DRAM 营收份额领先，并预告全公司季度经营利润约 800 亿美元（去年同期 90 亿）；SK 海力士录得 628 亿美元利润。代价由下游承担：今年夏天欧洲笔记本和台式机均价出现两位数上涨、PC 出货量下滑，智能手机出货量跌去至少五分之一，廉价机型被挤出市场。

**推荐理由**：AI 基建的成本正在以最朴素的方式外溢到每一个普通消费者的账单上，这是今年硬件行业最确定的宏观趋势。

## [Anthropic 知情半年不修：Claude Dispatch 漏洞让浏览器插件能跨机器执行代码](https://www.theregister.com/research/2026/11/05/anthropic-wont-fix-a-claude-dispatch-flaw-that-could-let-attackers-execute-remote-commands-across-corporate-boundaries/5307684)

安全研究者 Gal Weizman 发现，Claude 的 Dispatch 功能（把任务从手机或浏览器派发给桌面端 Claude Desktop 执行）的接口和 API 可以被一个普通的已登录 claude.ai 网页会话直接触达。这意味着任何能控制 claude.ai 页面的浏览器扩展，都能以合法 Dispatch 用户的身份向 Claude Desktop 下发命令——而 Claude Desktop 是一个能在本机运行命令的 Agent，甚至能打到同一账号登录的**另一台**机器上。Weizman 称之为"教科书式的权限提升"，并指出 claude.ai 月访问量约 9.5 亿次。他在 5 月就上报了这个被命名为 ThisBash 的问题，Anthropic 确认有效但以"与已知问题重复"关闭，既没发赏金也没发 CVE，只承诺十月底下线 Dispatch——然而并没有下线。

**推荐理由**：桌面 Agent 把"浏览器里的网页权限"和"操作系统执行权限"连通了，这类跨信任边界的结构性风险才刚开始浮现。

## [百度开源 ERNIE-5.5-Flash-Base：280B 总参数 MoE，只放预训练后的裸权重](https://ernie.baidu.com/release/ernie-5-5-flash-base/)

百度发布 ERNIE-5.5-Flash-Base，一个 280B 总参数、每 token 激活 14B 的稀疏 MoE，从零在 33.5T token 上预训练，训练上下文 128K，微调与推理支持 1M token。与多数开源发布不同的是，这次放出的是**预训练结束、任何中期训练和后训练之前**的检查点——官方明确把它定位成一个供领域适配、指令微调和强化学习研究共用的起点。效率是全程的设计目标：注意力、残差连接、MoE 层与输出头都按"激活算力 + KV 缓存 + 长上下文成本"三者合并权衡，而非逐项单独优化；语料则刻意偏向仓库级代码与长上下文理解这类"事后很难补上"的能力。

**推荐理由**：开源裸基座模型比开源对齐后的聊天模型稀有得多，对想做定制化、垂域适配的团队，这是个比成品模型有用得多的起点。

## [Together AI 把推理编译交给 Agent 持续跑：实验吞吐提升 252 倍，最高 2.6 倍加速](https://www.alphaxiv.org/abs/2611.together-compiler-continual-ai-inference)

Together AI 公开了其生产环境的 Together Compiler（TKCC）。核心痛点是流量形态一直在漂移——同一个模型在某国是 Agent 负载、在别处是聊天负载，输入长度可以在工作时段与非工作时段之间差出 27k token。现有方案在"测量保真度"和"实验吞吐"之间二选一：优化单个 kernel 用随机数据快但失真（随机数据会比真实流量多激活 13–38% 的专家），端到端优化真实但每次要等十分钟的引擎冷启动。TKCC 的办法是分层常驻引擎：引擎只加载一次，热替换 forward 函数指针并重新捕获 CUDA 图，快层只跑 12 层用于高频迭代、慢层跑全部 60 层用于高保真验证。结果是在 24 小时、至多两个节点内，对 Kimi K3、GLM 5.3、DeepSeek v4.1 Flash 等前沿模型取得最高 2.6 倍 TPS 提升。

**推荐理由**：最反直觉的是论文的"苦涩教训"一节——他们逐一删掉了专家知识库（反而快 25–31%）、专家策略提示（不如一句"把这个 forward pass 跑得尽量快"）和研究日志数据结构，把一切交给 Agent 后性能上限反而更高。

## [Discord 彻底抛弃 Electron，整个客户端迁往 Rust，内存降到 290MB](https://www.theverge.com/news/1027379/discord-ditching-electron-web-app)

Discord 宣布放弃 Electron——那个让开发者用 Web 技术写桌面应用、同时以吃内存著称的框架——把桌面客户端整体迁移到 Rust。CTO Stanislav Vishnevskiy 在 X 上说明了范围："我们从 2018 年起就是 Rust 的早期采用者，很多基础设施、语音技术乃至当前客户端的一部分已经是 Rust 了，圣杯是把整个客户端搬过去。这意味着 Electron 没了，React Native 也没了；移动端保留原生 UI，但通过 Rust 与桌面端共享应用代码。"他同时放出一张 Windows 客户端只占用 290MB 内存的截图作为佐证。

**推荐理由**：Electron 几乎定义了过去十年的桌面应用形态，而 Discord 是它最大的用户之一。这次迁移会是 Rust 在终端 GUI 领域最有说服力的一个规模化案例。

## [Meta 收购 AI 编码创业公司 Conductor，其云端沙箱 11 月 20 日关停](https://www.theregister.com/ai-and-ml/2026/11/05/meta-brings-conductor-on-board-its-model-train/5307711)

Meta 收购了 AI 编码创业公司 Conductor，未披露价格。Conductor 的产品是一个 macOS 应用，能在 Git 项目的多个隔离副本中同时运行多个编码 Agent。联合创始人兼 CEO Charlie Holtz 在博客中宣布，托管版 Conductor Cloud 将于 11 月 13 日转为只读、11 月 20 日彻底关停；本地 macOS 应用还能再用几个月，但 2027 年初起不再接入新模型、也不再修关键 bug。Meta 发言人确认此次收购将强化其面向开发者的 AI 能力，但拒绝细说。此前 Meta 在四月竞购 Manus AI 的 20 亿美元报价被中国监管否决后，收购胃口明显收敛，今年的几笔（Moltbook、Assured Robot Intelligence、Stilla）规模都不大。

**推荐理由**：编码 Agent 赛道的整合正在加速，而"被收购后云端服务两周内关停"也再次提醒：把工作流绑定在小团队的托管服务上，代价随时可能到来。

## [Nvidia RTX Spark 笔记本在 Linux 下只跑出 Windows 的 21% 性能，根因是加密的固件功耗表](https://www.mindstudio.ai/blog/linux-nvidia-rtx-spark-laptop)

MindStudio 在 MSI Prestige N16 Flip AI Plus 上实测双系统：Linux 能装、能跑，Nvidia 开源内核驱动带来 GPU 加速、4K 120Hz 输出、音频触控板一切正常——唯独一插上电源，GPU 频率就被锁死在约 780MHz，而 Windows 下能跑到 2.2GHz 以上。在 GPT-OSS-120B 上的差距非常直白：Windows 65.4 tokens/s，WSL 65.1，Nvidia 自家 DGX Spark 61，而原生 Linux 只有 13.9。根因是一个叫 Nvidia Platform Controllers and Framework 的 Windows 独占组件负责 CPU 与 GPU 之间的功耗调度，固件的功耗表是加密的、只有 Windows 驱动能解密，Linux 无从读取。更讽刺的是，想在 Linux 下让 GPU 看到超过一小部分内存，还得先回 Windows 改那个只有 Windows 才暴露的 96GB 统一内存分配开关。

**推荐理由**：本地跑大模型的新一代便携硬件，在最该服务的 Linux 用户面前被自家闭源固件挡住，这是"AI PC"叙事里一个很值得记录的裂缝。

## [白宫网络被发现是住宅代理出口节点，30 天内出口 236 次](https://www.theregister.com/security/2026/11/05/the-white-house-is-apparently-a-popular-residential-proxy-exit-spot/5307969)

安全公司 Layer3 Intel 在自家住宅代理观测平台上偶然发现，AS2650——注册方是总统行政办公室、承载白宫网络——出现了住宅代理出口活动。10 月 5 日至 11 月 3 日间，他们的探测流量从白宫网络出口了 236 次，涉及 6 个 IP 地址、30 天中的 26 天，共有 28 家不同的住宅代理服务能从这里出去。研究者强调这不是定向探测，而是购买全球轮换出口时撞上的；Spur、Synthient 等独立检测服务的公开 IP 画像也各自把这些地址标为住宅代理出口。活动时间分布尤其耐人寻味：约一半集中在美东时间下午五点到午夜，清晨几乎没有——这个模式更像某个长期在白宫网络上待到深夜的个人设备被植入了代理 SDK，而非公共访客 Wi-Fi。

**推荐理由**：任何人花几美元就能让流量从白宫 IP 出去，这既是一起具体的安全事件，也是对住宅代理这个灰色产业规模的一次直观测量。

## [Claude Code 把用户邮箱塞进 User-Agent 发给任意网站，引发隐私争议](https://github.com/anthropics/claude-code/issues/107757)

一名开发者提交 issue 称，Claude Code 在执行网页搜索时把他的邮箱地址放进 HTTP 请求的 `User-Agent` 头，发送给了任意第三方站点，而他从未授权此行为；他表示自己因此每天收到几十封诈骗邮件，并已决定把公司迁走。他的论点是这不该是一个"可选择退出或加入"的设置，而应当从 harness 中彻底移除：这个字段对不欢迎 Agent 流量的服务毫无帮助，也保护不了用户的匿名性，却是诈骗者的金矿。该 issue 开出不到一天已累积 27 个表态，截至发稿仍处于 open 状态。

**推荐理由**：编码 Agent 替用户发出的每一个网络请求都在替用户做身份暴露的决定，而这类默认值往往没有经过任何用户知情环节。

## [用一个冷门音频编解码器，让 N64 以 4% CPU 占用播放 44.1kHz 立体声](https://phoboslab.org/log/2026/11/n64-ulc-codec)

Dominic Szablewski 复盘了 N64 的音频困境：PlayStation 能直接从 CD 流式播放未压缩音轨，而 N64 的卡带空间寸土寸金、93MHz 的 CPU 时间也紧张，更关键的是向量协处理器 RSP 的直接编程权限被任天堂长期把持，第三方只能通过 Libultra 用现成的 ADPCM 方案——压缩比只有 4 倍，一首 5 分钟的 44.1kHz 立体声仍要约 12MB，而整个《马里奥 64》ROM 才 8MB。于是 N64 游戏的配乐普遍采用 tracker 式做法：调度短采样加有限效果，完整录制的音轨基本无从谈起。后期少数获准直接写 RSP 的开发者中，《康克的坏毛病》用它解 MP3 来播放海量语音，但解码开销大到拖累帧率，只够用在过场动画。作者的方案把这两头都绕开了。

**推荐理由**：把一台 1996 年主机的工程约束讲透，再用现代眼光找出当年被错过的解法——这类考古式的硬件写作读起来格外过瘾。
