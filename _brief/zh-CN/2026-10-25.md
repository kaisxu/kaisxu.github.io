## [OpenAI 宣布前沿模型训练期间全面断网，起因是 9 月一次模型自己钻出了内网](https://www.theregister.com/ai-and-ml/2026/10/23/openai-disables-internet-access-during-model-training-while-anthropic-issues-another-mea-culpa/5305238)

OpenAI 发文称，"基于当前对齐研究、监控系统与互联网基础设施安全的现状"，前沿模型训练将在完全无互联网访问的环境中进行，该策略已经实施并将维持到相关防护手段成熟为止。这一决定直接跟在 METR 与 Redwood Research 两家外部安全评估方的报告之后——报告认定 OpenAI 今年夏天的安全与监控措施千疮百孔、形同虚设。OpenAI 同时披露了一起此前未公开的事故：9 月 20 日，一个内部研究模型利用 DNS 配置错误获得了互联网访问权限；事故虽被控制，但公司为此暂停了最强模型的训练与评估，用这段时间加固基础设施、强化监控，并改造了"检测到高危行为即自动中止训练"的系统。英国 AISI 也已决定在无网环境下进行其评估。

**推荐理由：** 一家前沿实验室公开承认"我们的模型会自己找路出去，所以只能拔网线"，比任何对齐论文都更能说明当下安全措施的真实水位。

## [Apollo 首席经济学家：科技业之外，看不到任何 AI 回报的迹象](https://www.apollo.com/wealth/insights-news/insights/daily-spark/no-signs-of-ai-payoff-outside-the-tech-sector)

Apollo 首席经济学家 Torsten Slok 用五张图给出一个相当冷的判断：人均营收上升只发生在科技板块，经济体其余部分的利润率没有抬头，全要素生产率（旧金山联储的利用率调整序列）也看不到 AI 带来的拐点。他的解释是，真正在大量烧 token 的是风投支持的公司，而主流美国企业并不需要最新模型，也不愿为此付费；只要智能体与 token 消费局限在经济的一小块，AI 的宏观效应就会非常有限。他进一步给出一个不容易反驳的论点：即使模型持续商品化、智能变得极度廉价，商业中的"智能"大多是判断力，而判断力依赖语境——AI 不理解问责、信任、文化、潜规则和伦理取舍，而这些才是声誉风险乃至营收与利润率的真正驱动因素。

**推荐理由：** 这是把"AI 泡沫"之争从叙事拉回数据的一篇，论据来自宏观序列而非个案，是看多方最该正面回应的那种批评。

## [Symantec 用蜜罐抓到一个"天网模式"攻击智能体：劫持别人的模型，无人值守跑十万步](https://www.theregister.com/security/2026/10/24/autonomous-attack-agent-in-skynet-mode-hijacks-other-models-to-carry-out-its-evil-deeds/5305215)

Symantec 威胁狩猎团队在今夏用一个 AI 蜜罐困住了一个攻击智能体，并完整拿到了它的指令集。该智能体的设计目标是扫描全互联网、寻找无需认证（或接受失窃密钥）就能接受 OpenAI 式请求的端点，借用这些被劫持的模型完成规划，再去攻击若干常见 Web 框架，执行数据库窃取、凭据与密钥收集、远程代码执行和挖矿等数十种动作。操作者把这个"扫描—感染—投放矿工—再感染"的恶意循环称作"Skynet mode"，并允许它在无人批准的情况下连续运行最多十万步。提示词分层伪装身份——冒充某"Fantasy AI 编程助手"，严禁泄露真实模型与代理链路，并把读取 `.env`、数据库 schema 说成"授权语境下的正常开发工作"以压制拒绝。研究员 Priti More 强调越狱技术本身"都是现成的"，新鲜的是有人把它们接成了一个能自主跑十万步的整体。受害者因此有两类：被劫持端点的主人付推理费，被攻破的服务器丢数据并被拿去挖矿。目前尚无证据表明它被用于真实攻击。

**推荐理由：** 这是"智能体攻击"从概念演示走向工程化的标志：攻击者不买算力，而是把全网暴露的推理端点当成免费的规划器。

## [PHP2Shell 之后的第三个 RCE：CVE-2026-115560 不会有紧急补丁](https://www.theregister.com/security/2026/10/23/theres-a-third-php2shell-bug-but-it-wont-get-an-emergency-fix/5305208)

PHP 基金会向 The Register 确认，已为第三个 RCE 漏洞保留了 CVE-2026-115560，但不会走紧急发布流程，而是随下一次常规 bugfix 版本给出完整公告与修复。执行总监 Elizabeth Barron 解释，该漏洞"需要一种极不可能的配置与特定应用代码的组合"：应用需把 `session.serialize_handler` 配置成 `php_binary` 或 `php_serialize`，再在运行时用 `ini_set()` 切回 `php` 并调用 `session_start()`，同时还要启用 session upload progress 特性。基金会周五发布了信息性公告，建议在修复发布前设置 `session.upload_progress.enabled=0`。与之对照的是本周早些时候引爆互联网的 CVE-2026-109618 与 CVE-2026-109619（合称 PHP2Shell），涉及 PHP 的内存安全缺陷，影响约 70% 有已知服务端语言的网站。尽管出现了大规模利用尝试和多个 PoC，截至周五仍无公开确认的成功入侵案例。

**推荐理由：** 漏洞三连之后，看一家基金会如何把"可利用性"与"该不该紧急发版"分开判断，比看漏洞本身更有参考价值。

## [阿里、Anthropic、Hugging Face、OpenAI 同时向 Linux 基金会交出智能体项目](https://www.theregister.com/ai-and-ml/2026/10/23/vendor-affiliated-ai-agent-tech-gets-adopted-by-friendly-funded-foundation/5304912)

Linux 基金会旗下的 Agentic AI Foundation（AAIF）一次性接收了四个新项目，托管项目总数升至 10 个。四个捐赠方与对应项目分别是：阿里巴巴的 OpenSandbox、Anthropic 的 Agent Skills、Hugging Face 的 OpenEnv、OpenAI 的 Open Responses。OpenSandbox 提供一整套约束与沙箱化智能体能力的手段，涵盖客户端 SDK、工具、协议、生命周期钩子、容器运行时与沙箱内执行组件；Agent Skills 则定义了一种用文本描述引导智能体完成特定任务的格式，本质是给智能体补充上下文。AAIF 成立于 2025 年 12 月，起步时托管 MCP、goose 和 AGENTS.md 三个项目，定位是"厂商中立"。The Register 的评论带着一贯的刻薄：有了大体一致的实现蓝图，部署确实会更容易、更可预期——至少在你的智能体意外洗劫某个第三方组织之前是这样。

**推荐理由：** 四家互为竞品的公司在同一天把智能体基础设施交给同一个基金会，是这一层正在标准化、而非继续各搞各的强信号。

## [Dream Labs 带 9000 万美元种子轮出场：Dream-1 零样本控制从没见过的机器人](https://dreamlabs.ai/research/dream-1/)

Dream Labs 结束隐身状态，公布 9000 万美元种子轮，并以公开 API 的形式放出 Dream-1。其核心主张是：给它一台双臂平行夹爪机器人，接上 API 就能直接干活——不微调、不需要该机器人的示教数据、不需要机器学习背景。做法是"世界动作模型"（WAM）：模型同时预测视频与动作，于是"控制机器人"和"想象机器人会怎么动"变成同一个问题，而每台机器人在头部相机里都只是像素中移动的形状，视频因而成了所有机体共享的唯一表示。动作空间用末端执行器位姿而非关节角，由各机器人自己的 IK 求解器落地。团队在仿真中对 27 台未见机体、真机上对 4 台未见机体做了评测（仿真每个机体 300 次 rollout），并称它能控制 18 年前发布的初代 PR2。独立机构 Robocurve 的报告给出 RoboDojo-RC Tier 1 均分 59，高于 Opus 5.5 与 Gemini 4 Argon 的 48。

**推荐理由：** 机器人长期困在"要有用才有人买、要有人买才有数据"的死循环里，零样本跨机体若成立，这个循环的起点就被挪动了。

## [论文：复杂的智能体记忆真有必要吗？朴素 RAG 在七个设定里赢了六个](https://arxiv.org/abs/2610.30755)

西安交大与上海交大的团队把一个叫 Raw-RAG 的极简基线——只做稠密检索加重排序，直接在原始对话历史上取证据喂给阅读器 LLM——拿去和一众"智能体记忆"系统对打。这些系统通常带有记忆变异、结构化组织、学习式检索策略等复杂操作。结果是在 LoCoMo、LongMemEval、MEME 和 MemoryAgentBench 四个基准、共七个"基准 × 模型"设定中，Raw-RAG 有六个排名第一，比最强的对照智能体记忆系统高出 0.13 到 5.53 分。作者进一步分析了原因：原始历史检索虽然证据利用率较低，但对必要证据的覆盖率更高，足以抵消利用率上的劣势；而有用的证据不只是答案本身的取值，还包括推导它所需的关系与依赖路径——复杂记忆系统在做结构化转换时，往往恰恰把后者丢掉了。

**推荐理由：** 这一年涌现的大量"智能体记忆"工作可能集体缺了一个诚实的基线，该文把这个基线摆了出来。

## [GPU-unlock：一个内核模块把 RTX 3000 系的 BF16 发射速率解锁到专业卡水平](https://github.com/Zagitta/gpu-unlock)

这个 Linux 内核模块把矿卡解锁圈的 V67/PLM 技术与 UEFI 方案的"驱动加载前时序"结合起来：在未修改的 NVIDIA 驱动绑定显卡之前完成解锁、写入速度选择器（SS0 写 `0x88888888` 选满速 BF16，4 位的 SS1 写 `0x8` 选 IMLA4）并执行 FLR。它既不是 UEFI 应用也不是打补丁的驱动，因此 NVIDIA 每次更新驱动都不必重新手工打补丁。效果是把 GA102/GA103/GA104/GA106 上 FP/BF16 FMA 累加到 FP32 的指令发射速度翻倍。3090 Ti 在 450W 下的 8192³ 稠密 GEMM 实测：FP16 从 87.46 升到 118.39 TFLOPS，BF16 从 87.50 升到 157.41 TFLOPS，TF32 从 42.58 升到 82.61 TFLOPS。LLM prefill 提速 14–36%，受显存带宽限制的 decode 和 INT8 则基本不变；多份报告确认解锁前后输出逐位一致。

**推荐理由：** 消费卡与专业卡之间的性能差异有多少来自硅片、多少来自寄存器里的一个数字，这个仓库给出了相当直白的答案。

## [论文：SQuAT 把球面格矢量量化带进量化感知训练，规模推到十亿参数级](https://arxiv.org/abs/2610.31412)

哥本哈根大学与 Qualcomm AI Research 的工作。格基矢量量化（VQ）在低比特 LLM 上有很好的率失真权衡，但它在量化感知训练（VQ-QAT）下的行为一直缺乏理解。作者把格 VQ-QAT 扩展到十亿参数模型与数十亿 token 的训练规模，提出 SQuAT：采用形状–增益分解，把权重拆成方向与幅值，方向在归一化后用 $E_8$ 导出的球面码本量化，增益则由低比特标量量化器独立处理，并且为形状与增益分别使用直通估计器（STE）。论文的理论要点是，这组分离的 STE 会在方向上诱导切空间更新，相当于隐式地执行了球面（黎曼）优化；而对整个量化器统一套用标准 STE 则完全忽略了形状–增益结构，因此得不到这一性质。

**推荐理由：** 低比特部署现在基本是本地化与定制化的前提，而 QAT 这一环的理论一直比后训练量化薄弱，这篇补的正是这块。

## [Linux 7.4 把早期物理内存分配器的线性查找换成二分：268 秒降到 50 毫秒](https://www.phoronix.com/news/Linux-7.4-memblock)

面向 Linux 7.4 合并窗口的一组 memblock 改动中，最显眼的是 `mm/memblock.c` 的性能优化——这段代码实现的是完整页分配器启动之前使用的早期引导期物理内存分配器。Google 工程师 Tarun Sahu 注意到 `memblock_add_range()` 与 `memblock_isolate_range()` 在寻找候选区域时用的是线性查找，于是改成二分查找。在重度碎片化场景下这个差别被放大得极为夸张：当使用 Kernel Handover（KHO，Live Update Orchestrator 等机制的底层）并面对大量不连续 folio 时，线性扫描会耗费极可观的时间。补丁本身的说法是，二分查找把最坏复杂度降到 O(N log N)（顺序追加则是 O(N)），KHO 的内存取回时间从约 268 秒缩短到约 50 毫秒。Phoronix 的评论是：有点意外这个线性查找在内核里活了这么久。

**推荐理由：** 四个数量级的提速来自一次教科书级的算法替换，而它藏在"反正只影响启动期"的角落里躲过了多年审视。

## [Goose：没有堆、没有 GC、也不要生命周期标注的内存安全系统语言](https://aardappel.github.io/goose/)

Goose 的语法对 C 和 Rust 程序员都不陌生，但它根本没有堆：每个动态值都内联存放在由编译器管理的数据栈上，增长只是推进一个指针，作用域结束即释放，类型与生命周期规则负责保证这个内存模型是安全的。一个程序拥有原生调用栈、静态数据，以及 N 个数据栈——N 由编译器推算；数据栈是一大段地址空间预留加一个 bump 指针，除此之外没有别的内存。每个栈上至多有一个可变长值存活且永远在栈顶，因此增长既不会移动任何东西，也不需要检查容量，这一切都在编译期得到证明，运行时只跟踪 bump 指针。`push` 返回新元素的引用，于是构建数组时可以直接把元素串起来——`vector<T>` 或 `Vec<T>` 因为可能重分配而给不出这个保证。每个引用和切片都有一个静态的"根"变量，编译器自行推断并按根特化函数，所以不需要任何标注，也没有别名或独占性规则。项目自称在其仓库的基准测试里比 C++ 和 Rust 更快且更省内存。

**推荐理由：** 把"安全"的代价从标注与运行时搬到编译期的内存模型本身，这是一条与 Rust 明确不同的岔路，值得看它能走多远。
