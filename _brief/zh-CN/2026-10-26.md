## [GitHub 令牌大规模滥用：Gheist 用一个六行工作流偷走 850 个账号的全部密钥](https://www.wiz.io/blog/gheist-attempted-scaled-abuse-of-stolen-github-tokens-stumbles)

Wiz 研究团队自 9 月 15 日起追踪一场名为 Gheist 的行动：攻击者拿失窃的 GitHub 令牌，向其有权限的每个仓库提交一个叫 `sync-check` 的工作流，让它把仓库 secrets 打印进自己的运行日志，随后通过 GitHub API 把日志拉走、几秒内删除运行记录。目前已恢复 850 多个被攻破账号下的 1.3 万多个植入分支，从个人项目一直到企业组织的私有仓库。三个细节让它奏效：GitHub 只在 secret 逐字出现时才做日志遮蔽，base32 编码一过就完整打印；`permissions: {}` 限制的是 `GITHUB_TOKEN` 而非 secrets 上下文；仓库若配了部署环境，工具会用 job matrix 遍历，把环境级的生产凭据一并打出来。因为数据是从 GitHub 自家 API 出去的，没有任何可封禁的攻击者域名或外联连接。

**推荐理由：** 把数据外带伪装成平台自身的合法 API 调用，让以"拦截外联"为核心的检测体系整体失效，这是供应链攻击的范式转变。

## [Cerebras 公开万亿参数部署方案：59 片晶圆流水线跑 3T 的 Kimi K3](https://www.cerebras.ai/blog/how-we-deploy-trillion-parameter-frontier-models-on-cerebras)

单片 Cerebras WSE-3T 晶圆只有 44 GB 片上内存，而万亿参数模型光权重就要几个 TB。Cerebras 以开源的 Kimi K3（约 3T 参数、69 层线性注意力 + 24 层稠密）为例算了笔账：4 bit 存权重、93 层平摊下来每层约 16 GB，按层类型装箱后共需 59 片晶圆，整模型以流水线方式铺开，每片晶圆承担一到两层。关键在于层能完整装进片上 SRAM，所以权重根本不用搬动，跨晶圆只传激活值，走 RDMA over Ethernet，每跳约 2 微秒。至于"流水线岂不是等于 batch size 为 1"的常见误解，答案是用不同请求把整条流水线填满，每个 stage 同时处理不同请求。该方案对多万亿参数模型可达每秒 1000–2000+ token。

**推荐理由：** 把"显存装不下就切开"的通行做法反过来做成"每层都不切、只让激活走"，是与 GPU 集群完全不同的一条推理路线。

## [十年前的 CNN 在皮肤癌识别上击败前沿大模型：62% 对 42%](https://lynchlab.net/llm-skin-cancer)

作者取 MILK10k 公开数据集中 200 例经病理活检确诊的皮损，每例都有临床照片和皮肤镜照片两张图，同时交给 GPT-6 Astra、Claude Fable 5.1 和一个微调过的 Inception v3。后者是 Google 2015 年发表的卷积网络，在单张 H100 上用 ISIC 归档的 68,011 张图微调约二十分钟，测试集的同病灶、同患者图像全部事先剔除。六选一诊断的正确数：CNN 125 例（62%），两个前沿大模型分别 84、85 例（均 42%）。文中给出的典型失败案例是一例色素极少的浸润性黑色素瘤，GPT-6 Astra 以 95% 置信度判为基底细胞癌。该 CNN 小到能靠 WebGPU 完整跑在手机浏览器里，作者提供了在线试用。

**推荐理由：** 在有大量标注数据的窄任务上，专用小模型仍然碾压通用大模型——而且小到能装进浏览器，这是"小型化与定制化"最直白的论据。

## [OpenAI 与 Anthropic 几个月内把价格砍掉最多 80%，到底为什么](https://minimaxir.com/2026/10/cheap-llms/)

minimaxir 梳理了两家近几个月的发布与调价时间线：OpenAI 把 GPT-5.6 Luna 直接降价 80% 到 $0.20/$1.20/$0.02，又给 GPT-5.6 Sol 临时降价约 20%；Anthropic 把 Sonnet 5 的"临时"发布价永久化，Fable 5.1 在全面提升性能的同时把缓存读取成本砍掉 75%。作者特别指出缓存读取这个常被当作脚注的项目：智能体编码场景下，缓存读取占 token 总开销的 96%–99%，命中率在 90%–100%，所以缓存降价 75% 约等于总体使用成本下降 70%–75%。最富戏剧性的一天是 OpenAI 发布 GPT-6 Sol（$2/$10/$0.20，相比上代腰斩）的同日，Anthropic 发布 Opus 5.5 并明示"服务它所需算力更少，定价已反映这一点"，总成本降低 40%–60%。

## [小模型学会选工具：8B 的 Qwen3 在 ToolBench 上打赢 402B 的 Llama-4-Maverick](https://arxiv.org/abs/2610.31483)

Meta 与 CMU 的工作。当智能体面对上万个可调用工具时，工具描述塞不进上下文，而检索器只能按相关度排序、并不知道任务究竟需要哪些，于是近期做法是让 Claude 或 ChatGPT 这类商用大模型以 ReAct 方式驱动检索器。作者证明这件事可以训进小模型：在极简的 Plan–Retrieve–Select 流程下（规划拆解子步骤、BM25 取候选、选择器挑工具），用教师轨迹做 SFT 再接 GRPO 强化学习，Qwen3-8B 在 ToolBench G3 上的严格精确匹配成功率达 41.5%，1.7B 也有 37.6%，而 402B 的 Llama-4-Maverick 在四种提示工作流下最高仅 30.6%。更关键的是迁移性：G3 上训出的同一份权重零样本迁移到 G2、Gorilla、CRAFT、TaskBench，并且把训练时用的 BM25 换成稠密检索器 COLT 后无需重训、性能还能继续上涨。

**推荐理由：** 工具选择是智能体管线里反复调用的子程序，把它从"每次调用前沿模型"变成"一个 8B 本地模型"，直接改变智能体的成本结构。

## [Polars 2.1.0 发布：一整轮围绕内存外溢与流式执行的性能重写](https://github.com/pola-rs/polars/releases/tag/py-2.1.0)

Polars 在 2.0 发布不到三周后放出 Python 2.1.0，变更列表里性能项占压倒性多数，主线是把流式引擎的内存外溢（out-of-core）行为做实：文件读取器在超出内存预算时会等待 spill 完成、排序刷写时限制预排序桶的内存、数据外溢后立刻把释放的内存交还操作系统、默认 spill 压缩级别降到 1 并复用 zstd 上下文、默认外溢预取比例下调到 0.5。此外流式 group-by 自行聚合 unique/n_unique、窗口节点可在核外求值、嵌套 Parquet 层级直接从 level buffer 编码、宽行 CSV 扫描内存下降，以及若干连接与排序的优化器改写。唯一的破坏性变更是 eager 模式下禁止字符串与数值的混合算术。

**推荐理由：** 一个 Rust 写的 DataFrame 引擎正把"内存不够就崩"系统性改造成"内存不够就优雅降级"，这是它从快变成可用于生产的那一步。

## [FPGA 上的连续概率计算机：7 位因数分解核心耗时比 QUBO 快约三万倍](https://arxiv.org/abs/2610.31339)

新加坡国立大学与阳明交通大学的团队做出了首个可编程"连续概率计算机"（CPC）的硬件演示。传统概率计算用二值 p-bit 加 sigmoid 更新，要表示连续变量只能拿多个 p-bit 拼出有限精度，单元数和耦合复杂度都随之膨胀。CPC 的每个 CP-bit 直接表示一个有界连续变量，从由局部能量决定的条件分布中采样；常数、线性、凸二次、三次的局部能量分别对应均匀、截断指数、截断高斯和非高斯条件分布。架构的关键是把随机源生成与条件采样分离，因而能适配 CMOS 的近高斯电压涨落或 RRAM 的对数正态阻值统计等不同物理随机源。KCU105 上的 FPGA 原型在 7 位因数分解上，相对所评测的 QUBO 软件实现把平均核心求解时间降低约 33,000 倍（连续表示贡献约 3,000 倍、FPGA 实现再贡献 11.1 倍，最终 95.59 μs）；MNIST 图样恢复最终成功率 100%。

**推荐理由：** 在数字芯片之外另起炉灶的计算范式里，这是少见的真把硅片做出来并给出端到端计时的工作。

## [Apple Silicon 上的推理优化集体失灵：投机解码全都在拖后腿](https://arxiv.org/abs/2610.31479)

来自 MacPaw、利沃夫理工与乌克兰国家科学院的团队指出一个被普遍忽视的前提错位：Apple Silicon 是本地 LLM 推理最常用的平台之一，而几乎所有推理优化都是在服务器级 NVIDIA GPU 的批量服务负载下设计和验证的。他们在四台 Apple 机器上以统一的单请求解码负载评测了四类优化，并尽可能与 RTX 4090 对照。结论相当刺眼：KV 缓存剪枝在 Apple 上端到端吞吐最高提升 1.75 倍，在桌面 NVIDIA GPU 上反而会掉；所有被评测的投机解码方法在 Apple 上一律降低吞吐，尽管它们在服务器 GPU 上报告过 2–6 倍收益；CUDA kernel 设计只能部分迁移——公开 Metal 没有异步拷贝，batch-one 解码又让若干面向服务的机制失效，可迁移部分最多带来 1.20 倍解码吞吐；量化收益则因机型而异。

**推荐理由：** "某技术加速 N 倍"这句话其实是技术、运行时、硬件契约与负载模式的联合函数，这篇把这个常被省略的限定条件量化了出来。

## [JetBrains 开源 ThinkRail：把编码智能体装进一个以 git worktree 为单位的 IDE](https://github.com/JetBrains/thinkrail)

JetBrains 开源了围绕 pi 编码智能体构建的 IDE ThinkRail，仓库已有 1600+ star，当前走 nightly 节奏（v0.3.0-nightly.6 于 10 月 25 日发布）。它的组织单位是 git worktree：任何仓库都能切出多个工作区，各自独立分支和工作目录，智能体并行作业而不碰你的 checkout，好的分支合掉、其余删除；PR 合并或闲置一周后工作区自动下架、再次使用时回来。顶栏显示当前分支相对 origin 和 PR 的状态，PR 开启后可看 CI 检查、把失败检查直接丢给智能体处理。持久知识靠一张相互连接的 `SPEC.md` 图，智能体通过专用 `spec_*` 工具读写维护，意图得以跨会话存活；此外复用已有的 Agent Skills 格式、接 pi 的 `mcp.json` 里的 MCP 服务器。

**推荐理由：** 主流 IDE 厂商开始把"工作区即 worktree、规范即事实来源"写进产品形态，这是智能体编码从插件走向一等公民的信号。

## [1984 年的《Sabre Wulf》被重制回 Commodore 64](https://gp-64.com/swr/)

Genesis Project 于 10 月 25 日发布 Sabre Wulf Remastered 的完成版，把 Ultimate Play The Game 1984 年的丛林迷宫游戏重新绘制并重新编程到 Commodore 64 上。发行形态完全遵循那个年代的惯例：以 D64 磁盘镜像分发，同日另有 Shadow 和 Triad 两个破解版本、附带 Stormfront 制作的训练器选项，成品的配乐也单独以 SID 文件提供，可在 SID 播放器或 VICE 里播放。标题画面由 Jon Eggelton 绘制，他在 2017 年就重新构想过 Sabre Wulf 的载入画面。项目方明确标注这是非官方同人重制，与 Rare Ltd. 和 Microsoft 无关，版权归属不变，且只有数字下载、没有盒装版。

**推荐理由：** 四十二年后仍有人为 8 位机写新游戏，连破解版和训练器这套发行仪式都原样保留，是复古计算场景最完整的一次标本。
