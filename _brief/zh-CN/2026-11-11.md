## [AMD Zen 6 完整规格公布，Verano 首次把 CPU 变成 AI 超算芯片](https://www.theregister.com/systems/2026/11/10/amd-winds-up-zen-6-cores-for-faster-clock-speeds/5308603)

AMD 上周在拉斯维加斯的发布活动上公布了 Zen 6 核心全貌：相对 Zen 5，云与 AI 工作负载 IPC 平均提升 20%–31%，频率区间 4.1–5.3 GHz，最多 256 核，且功耗、IPC、频率三项同涨，是 AMD 史上最大的一次代际跃升之一。架构上仍是两个核心——频率优化的 Zen 6 与密度优化的 Zen 6c，两者共享同一 ISA；关键差异在乱序流水线的调度器队列深度，Zen 6c 队列更深以适配高延迟负载，Zen 6 队列更浅但能跑更高频率。分支预测沿用 Zen 5 的方向预测器但降低了误预测恢复代价（每分支 3–3.5 ns 对 3.5–4 ns），L1i 内每周期可取两条分支；整数侧退回 Zen 4 的 NOP 配对、每周期 5.96 次 64 位加法（Zen 5 为 5.25），但整数乘法单元从三个减为两个。AI 相关的是原生 FP16 支持（此前需填充到 FP32，低精度几乎不省时间）与 VNNI-INT8 单元从 2 个增至 4 个，512 位测试吞吐从每周期 1.99 条升到 3.88 条。同场 AMD 首次披露 Verano：72 个 5.3 GHz 高频核或 192 个 4.1 GHz 密度核，用笔记本级 LPDDR5X 而非 RDIMM，xGMI 每通道 112 Gbps（接近 PCIe 7.0），直接焊在 BGA 封装上。AMD 计算与企业 AI 业务副总裁 Madhu Rangarajan 称 Verano 是走向 Vera Rubin 式超算芯片的第一步。

**推荐理由**：英伟达之外第一次有第二家在认真做「CPU 为 GPU 而生」的产品，xGMI 带宽是真正与 NVLink 竞争的那一栏。

## [AI 把 CPython 翻译成 61 万行 Lean：机器验出 418 个 Python 缺陷，约 55 个可崩溃解释器](https://broyojo.com/python-formalization/)

项目用 Opus 5.5 指向 CPython，把它的函数逐行改写成 Lean（机器可检验证明的语言），每个改写都要与真实 Python 在数万个刁钻输入上并排运行比对，任何不一致即判定改写有误，然后陈述一个应当恒真的命题交给计算机检查——若命题本身为假，就去证明它为假。计数门槛是第二个未参与改写的智能体复核通过者才算数。目前 4071 个函数通过复核，累计 61.3 万行 Lean、1539 个文件、18898 条定理与引理，每次构建都由 Lean 的证明检查器全量验证；CPython 3.15.2 的整体覆盖率为 14%，其中语法规则 100%、内置类型 35%、解析器 31%、C 模块 19%。过程中提交了 418 份缺陷报告，多数是小问题，但约 55 个能让解释器崩溃或破坏内存。团队坦承最初的失败模式：第一版按广度要求智能体为每个函数至少证一件事，结果审查发现被检查的函数里不到一半站得住，某个文件甚至只有 21%——证明全都正确，只是没有信息量，比如「若返回一个数则该数非负」对一个永远崩溃的函数也成立，于是审查问题改成一句话：坏掉的版本能否也通过这条证明。

**推荐理由**：对 CPython 这类三十年的 C 代码做全量形式化验证，第一次给出了「AI 生成的证明可能毫无意义」的量化教训。

## [论文：智能体负载的混合状态管理——FlashStates 与 Evolving Infra](https://arxiv.org/abs/2611.12304)

本期论文推荐聚焦一个具体问题：智能体工作负载正成为 LLM 推理需求的主要来源，但现有推理引擎的状态管理是按纯全注意力模型设计的。两篇同日投稿的论文从不同角度拆它。Together AI、UIUC 与 UT Austin 的 [FlashStates](https://www.alphaxiv.org/abs/2611.flashstate)（alphaXiv 首发，尚未上 arXiv）指出问题根源在混合架构：线性注意力/状态空间层要求在前缀的精确结束位置有一个循环检查点，而该位置不能像 KV 张量那样回滚——检查点只能落在 KV 缓存块边界上，导致 vLLM 与 SGLang 要么粗粒度复用前缀（重算本可复用的部分），要么在块对齐处密集打点（造成依赖缺失与缓存抖动，论文实测 SGLang 在 24–32 并发时 33%–43% 的未缓存 token 源于此）。其解法 Arbitrary State Checkpointing 把检查点位置与 KV 块边界解耦，再用一个依赖感知的 GreedyDual-Size 优先级统一决定准入与淘汰：在 B200 上跑 GLM-5.3-Flash、Nemotron 3 Super、Qwen3.8-Flash-Next 的编码智能体负载，prefill 吞吐分别达到 vLLM 的 3.14 倍、2.27 倍、1.54 倍，p90 首字延迟下降 88.4%、77.1%、79.0%。另一篇 Evolving Infra（Georgia Tech、UIUC、Berkeley、NVIDIA Research、OpenAI、MIT 等）攻击的是 prefill/decode 分离架构本身：节点按请求类型划分导致负载不均、KV 缓存被反复淘汰，它把计算分配与 KV 管理解耦、用在线规划器匹配负载构成、用智能体感知的分布式 KV 管理器指导淘汰与迁移，在最多 256 张 GB300 上，编码、数学与计算机使用任务相对 NVIDIA 的生产框架 Dynamo 把平均端到端延迟降低最多 4.1 倍、p95 首字延迟降低最多 14 倍。

**推荐理由**：智能体推理的成本结构正在被重新定义，而这两篇来自同日的论文给出了互补的两条解法路径。

## [一个 tar 包被八种工具解出八种结果：134 个畸形 tar 用例的实测](https://stoppels.ch/2026/11/07/the-hardest-tarball.html)

作者 haampie 用一条 GNU tar 命令构造出一个能被八种工具解出八种不同结果的归档：三次传入 file、./file 与 empty，使第二条以硬链接形式存储，再用 --transform 把硬链接改名成 café 触发 pax 头，pax 头中写入 size=512 覆盖硬链接的 size=0——而 512 恰好是一个 tar 头块的大小。POSIX 只说硬链接的数据块「可以」包含在 pax 归档中，语义并不明确，于是各家实现各行其是：GNU tar、BusyBox、Python、Go、Perl 忽略硬链接上的 size；macOS 的 bsdtar 更接近 POSIX 精神，把那 512 字节写进硬链接，导致 file 的内容变成 empty 的 tar 头；7-Zip、node-tar、tar-fs 以及 Rust 的 tar 与 astral-tokio-tar 同意那是数据但跳过它，结果 empty 整个丢失；Java 的 Commons Compress 另建一个只装着 empty 头部的文件；PHP 的 PharData 把 café 解成空文件又照样解出 empty；RubyGems 干脆不解 café，转而在旁边造一个空的 PaxHeaders 目录；R 则把 size 错套到 empty 上，从结束标记里读出 512 个空字节。Haskell 与 GNU tar 行为一致，只是字符串解码有 UTF-8 问题，把 café 变成 cafÃ©。.NET、Julia 与 uv 的 tar-codec 选择直接拒绝这个包——作者认为这反而是最好的答案，尽管严格说并不 POSIX 兼容。该 tarball 是作者自建测试集 tar-minefield 中的第 135 号，共 134 个刁钻用例。

**推荐理由**：tar 格式诞生于 1979 年、POSIX 规范写于 1980 年代，八十年后的今天其语义歧义仍能分裂整个生态——而 Python 与 Rust 都在分裂的那一边。

SpaceX 11 月 10 日发布第二代 Starlink Mini 便携卫星终端。核心变化是内置可拆电池：71 Wh 容量、重约 1.08 磅（490 克）、快拆结构无需工具即可更换，单次充电可提供约 4.5 小时连接；电池自带 LED 指示灯与 USB-C 充电口，支持 60 W USB-C PD，零售套装含 60 W 墙充与三米线。终端本体也可直接由 USB-C 供电，并新增了实体电源按钮（初代为即插即用）。机身 12.36 × 10.35 × 0.91 英寸（314 × 263 × 23.1 mm），比初代薄约半英寸，但含电池与支架后重 3.53 磅（1.6 公斤），初代为 2.43 磅。无线部分从 Wi-Fi 5 升到 Wi-Fi 6，集成路由器覆盖约 1800 平方英尺（167 平方米），防护等级 IP67，配备可折叠支架与标准三脚架螺纹孔。美国部分用户已可限量预订，价格 999 美元另加税，含一年 Roam Unlimited 服务。同日另一条同向的消息是苹果被曝在筹备名为 Harbor 的 Mac 应用：把多台 Mac 通过 Thunderbolt 5 互联成集群、把统一内存池成一个推理资源，从而运行单台机器装不下的开放权重模型，目前处于 Claris 品牌下的私有预览。

**推荐理由**：本地化与移动化正在合流——卫星终端自带电池，Mac 集群自带内存池，两条路都指向「算力随身」。
