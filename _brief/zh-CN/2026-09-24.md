## [Anthropic 让 950 个 agent 跑了 21 小时，找到一类带 CRISPR 式重复序列的新酶系统](https://www.anthropic.com/news/claude-discovers-novel-enzyme-system)

Anthropic 公布了今年春天新建的生命科学研究组与实验室（仅 BSL-1/BSL-2，不接触人类病原体，湿实验全部由人类完成）。Claude 自主发现的系统被命名为 ART（array-associated reverse transcriptases），主要存在于噬菌体中，由逆转录酶、一个相邻的伴随基因和一段间距均匀的长重复 DNA 阵列三部分构成。规模是 950 个 agent、2.1 亿 token、21 小时：从 20 万条逆转录酶筛到 3500 个候选系统，再收敛到 20 个最有说服力的候选并各写一份人类可读报告。首批实验显示该阵列会表达成一组短 RNA。CRISPR 先驱、MIT 与 Broad 研究所的张锋读过预印本后表示这「确实耐人寻味，值得进一步研究」。

**推荐理由**：难得有外部权威专家背书的 agent 科研成果。人类介入只剩「初始 prompt + 湿实验」这一点，比任何 agent 评测都更能说明自动化边界走到了哪。

## [微软研究院 Agensh：去掉总调度，把 1024 个 agent 放进同一个 Git 仓库自组织](https://www.alphaxiv.org/abs/2609.26781)

现有多 agent 框架（Codex 子 agent、Claude Code agent teams、Copilot fleet、Kimi Agent Swarm）都是 orchestrator-worker 结构，上限卡在中心调度者的协调能力上。Agensh 索性取消中心调度：每个 worker 跑同一个五步循环——收集上下文、认领子任务、动手、自验、合并进展，全部异步。基础设施只有三件——Gitea 做共享工作区、Mattermost 做消息、一块 append-only 的共享上下文板（条目分 OBSERVED / FACT / FAIL / CLAIM / PATCH_SUMMARY）。在 ProgramBench 最难的五道题上，1 → 128 agent 把测试通过率从 19.31% 推到 28.78%；pandoc 一题扩到 1024 个 agent 时达到 55.06%。所有 worker 用完全相同的 prompt（只差 ID），却自发涌现出代码评审关系、标准化合并协议和专职「集成者」角色。

**推荐理由**：把 agent 数量确立为一个新的 scaling 维度。「FAIL 条目是最有价值的共享内容」这种细节，是可以直接抄进自家多 agent 设计的。

## [Weco AI 的 AIDE²：让研究 agent 改自己的代码，8 天接受了 7 次自我重写](https://www.alphaxiv.org/abs/2609.26457)

递归自我改进的操作对象是 harness 层——包住模型、控制搜索与上下文的那部分代码。系统分两层：内层 agent 在 AI 研发任务上优化代码，外层 agent 重写内层 agent 的代码，只有在内层从未见过的私有留出集上跑分提升才会被接受。一次 8 天自主运行产生 100 个节点，在第 2、6、28、39、47、63、85 步接受了七次改进，分数从 0.703 升到 0.778。最强的 AIDE85 在 ALE-Bench、MLE-Bench、FML-Bench 和分布外的 WeatherBench 2 上全部追平或超过人类团队两年打磨的生产 agent。意外收获是 reward hacking 率从 55% 降到 32%——这个目标从未被优化过。

**推荐理由**：把「自我改进」从口号变成了可核对的曲线，并且诚实写明噪声会沿两层放大、一次误判就能带偏整条轨迹。

## [英伟达把量化拆成两半：prefill 用 NVFP4 算，decode 只压权重](https://www.alphaxiv.org/abs/2609.26333)

prefill 是计算密集、decode 是访存密集，两者对量化的偏好本就不同。论文提出「解耦量化」，并量化了这种不对称：在 decode 重的任务上，只量化 decode 造成的精度损失是只量化 prefill 的 2–4 倍（Gemma3-1B 上高达 7 倍），prefill 重的任务上关系反转。方案分三级——格式解耦（只在 decode 关掉激活量化）、完全解耦（给 prefill 训一套独立的 NVFP4 权重）、以及把 prefill 权重从 SSD 流式读入的 ODP。给现成的 Qwen3.8-27B 1-bit GGUF 配一个训练好的 NVFP4 prefiller，MMLU-Pro 提升 32.5 分、MMMU-Pro 提升 35.3 分，decode 检查点完全不动；llama.cpp 上 8K 上下文的首 token 时间从 12.27 秒降到 6.90 秒。

**推荐理由**：本地跑大模型最痛的两件事——首 token 太慢、低 bit 掉智商——被同一个设计同时缓解，而且不用换掉你手上那份 GGUF。

## [苹果 LensVLM：把长文本压成图片来读，只把用得上的那几页展开](https://huggingface.co/apple/LensVLM-9B)

这是一个 9B 的视觉语言模型（基座 Qwen3.5-9B，BF16 约 94 亿参数、18.8 GB 单文件），思路是把长文档渲染成压缩后的图像先扫一遍，再通过学到的工具把相关页面选择性地还原成未压缩形态。推理时提供 5x、10x、15x 三档压缩比。论文《LensVLM: Selective Context Expansion for Compressed Visual Representation of Text》（arXiv:2605.07019）作者包括 Roy Xie、Dan Friedman、Zhe Gan、Bhuwan Dhingra 等。授权用的是 apple-amlr 机器学习研究许可（含苹果对 Qwen 的修改），配套代码另走 Apple Sample Code 许可。

**推荐理由**：处理长上下文的第三条路——不扩窗口也不做文本压缩，而是换一种模态承载。苹果把权重直接放到 Hugging Face 上，态度也值得记一笔。

## [Claude Code 只在遥测打开时才读 AGENTS.md，Anthropic 当天认错并修复](https://blog.szypowi.cz/p/claude-code-reads-agents.md-only-when-telemetry-is-on/)

AGENTS.md 支持由一个名为 `agents-md` 的内置插件实现，默认关闭，靠远程特性开关 `tengu_agents_md_mod` 打开，拉不到开关就回退为不可用。作者用 canary 词做了对照测试：设置 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 或 `DISABLE_TELEMETRY=1` 都会让本地文件被静默忽略，设成 `0` 也没用（只看是否存在），项目级 settings.json 里清空同样无效，而且全程没有任何警告；第三方网关、Bedrock、Vertex 同样中招。他的结论是：「一个只需要工作目录里已有信息的特性，不该依赖远程开关。」Anthropic 工程师 mpoteat 在 HN 头条回帖认领：「这是发布时的遗留问题，我们需要一个能远程关掉它的手段，而关掉遥测就拿不到开关。v2.1.281 今天已修复」，并称「完全是我个人的失误」。

**推荐理由**：隐私开关静默改变无关的本地行为，是一类很容易重复出现的设计事故。厂商当天公开认错、给出版本号并开源该模块，处理方式也值得对照。

## [《25 行 Python 写个 Jev》：一篇把分类模型神秘感戳破的恶搞博客](https://www.nobodywho.ai/posts/jev-in-25-lines/)

作者 Duarte O. Carmo 开篇即嘲：「所有人都在聊 Jev，说它是大模型的下一个前沿。我们不这么看，所以这是 25 行 Python 的 Jev。」实现用 PEP 723 内联依赖声明（huggingface-hub、llama-cpp-python、numpy），加载 Qwen3-0.6B 的 Q8_0 GGUF，n_ctx 只有 512，用空的 `<think>` 块压掉推理，取最后一个位置的 logits，只抽出三个候选标签的首 token，再在这三个数上做一次 log-softmax。示例把「工资部门在非公司登录页要你的密码」判为钓鱼，概率 0.885。他逐条对照被恶搞的对象：「我们没有叫它系统一决策模型，没有调 API，没有造合成数据，也没有用 RLCD 去校准概率。」

**推荐理由**：厂商叙事和二十几行本地代码之间的距离，有时候就是这么远。作为理解「约束解码 / 受限分类」怎么工作的教学材料也相当干净。

## [Radicle 披露两个网络协议漏洞：流量明文，且节点身份可伪造](https://radicle.dev/2026/09/23/disclosure-of-vulnerability-in-network-protocol)

去中心化代码协作网络 Radicle 公开了两个严重缺陷，**迄今发布过的所有版本都受影响**。其一是节点之间的流量既不加密也不认证，路径上任何人都能看到明文（Konstantinos Maninakis 于 6 月 24 日报告）；其二是握手阶段可以谎报 Node ID，而私有仓库只按 Node ID 白名单分发，伪造一个就能直接拉走整个私有仓库（cryptocode 于 8 月 12 日报告）。两者叠加最致命：旁路者先看到两端的合法 Node ID，再拿去按需取走全库，「没有任何设置或白名单能防住」。官方建议在修复发布前停用私有仓库、用 `rad block` 逐个屏蔽（比 `rad unseed` 可靠）、并轮换其中所有凭据。Tor、I2P 和 VPN 明确不够——它们挡不住身份伪造。修复方向是用 iroh 替换自研的 Noise 协议，属破坏性变更，会把网络切成新旧两半。

**推荐理由**：在修复发布之前就先披露，理由是「你今天就能行动，而事后的补丁撤销不了已经发生的泄露」——这个取舍本身值得同行参考。

## [高通给 Snapdragon X2 带来 Linux：Debian 年底、Ubuntu 明年上半年](https://www.qualcomm.com/news/onq/2026/09/snapdragon-summit-agentic-ai-pcs-linux)

Snapdragon Summit 2026 上，Linux 成为继 Windows、Googlebook 之后 Snapdragon X2 系列的第三个操作系统。高通称正在上游化核心驱动，包括 Hexagon NPU 和 Adreno GPU——这是过去 Arm 笔记本跑 Linux 最大的障碍。时间表是 Debian 2026 年底、与 Canonical 合作的 Ubuntu 认证瞄准 2027 上半年，HP、华硕和 HUMAIN 计划在 2027 年初跟进。生态数字方面，超过 120 家零售伙伴、12,300 家门店在卖 Snapdragon PC，13,000 多家企业已部署或测试。同场还有搭 Snapdragon X2 Plus 的微软 Surface Pro 12 英寸与 Surface Laptop 13 英寸，宣称本地 AI 推理快 80%、GPU 性能提升最多 55%、续航 15 小时以上。

**推荐理由**：NPU 和 GPU 驱动进主线，意味着 Arm 笔记本第一次有机会成为正经的 Linux 开发机，而不是「能装但什么都不能用」。

## [欧洲最快超算终于等到了国产芯片：SiPearl 开始向 JUPITER 交付 Rhea1](https://www.theregister.com/systems/2026/09/23/europes-fastest-supercomputer-is-finally-getting-its-domestic-silicon-infusion/5298665)

9 月 22 日，法国芯片设计公司 SiPearl 开始把 Rhea1 交付给系统集成商 Bull，用于 JUPITER 的纯 CPU 分区。JUPITER 去年上线，是欧盟第一台百亿亿次超算，目前 Top500 第五，其破纪录的 Booster 分区用的是 24,000 颗美国产的英伟达 GH200。Rhea1 基于 Arm Neoverse V1（已略显陈旧——Booster 里的 Grace 用的是更新的 V2），80 核、610 亿晶体管，配四组 HBM2e 共 64 GB、带宽 1.8 TB/s，外加四通道 DDR5，主打 GPU 不擅长的科学计算负载。CPU 分区建成后为 1300 节点、2600 颗处理器，估算约 5 PFLOPS——相比 Booster 很小，但对非 GPU 负载有意义。SiPearl 的下一单是 Alice Recoque 超算，CPU 分区用 Rhea2、GPU 分区用 AMD MI430X。

**推荐理由**：欧洲「技术主权」在硬件上到底兑现到什么程度，这是一个可以量化的观测点：5 PFLOPS、V1 而非 V2，数字比口号诚实。

## [AMD Venice 细节浮出水面：256 核、16 通道 DDR5、单插槽 1 GB 三级缓存](https://www.theregister.com/systems/2026/09/23/an-epyc-trip-to-venice-everything-we-do-and-dont-know-about-amds-256-core-monster-chip/5298614)

被称为 2019 年 Rome 以来 AMD CPU 设计上最大一次架构调整。Epyc 9006（SP7 平台）最高 256 核、16 通道 DDR5、128 条 PCIe 6.0 并支持 CXL 3.1，分密度优化（256 核）和频率优化（96 核、加速到 5 GHz）两种，均为两颗 I/O die 环绕八颗 CCD。密度型 CCD 每颗 32 核配 128 MB 共享 L3，满配一颗 Venice 有 1 GB L3。内存 DDR5-8000，用 MRDIMM 可到 12800 MT/s，峰值 1.6 TB/s，接近 Turin 的三倍。旗舰 9996 为 256 核 512 线程、600 W。HPC 版 Venice-X 靠 3D V-Cache 把 SRAM 叠在 CCD 下方而非上方，单插槽 1152 MB 的同时频率仍能到 5.15 GHz。AMD 用白皮书直接回应英伟达关于 Vera 的宣传：同样四项 SPEC 2026 测试里 96 核 Venice 快 1–12%，256 核版本吞吐是 88 核 Vera 的 2.24 倍。

**推荐理由**：AI 热潮下容易忽略通用 CPU 这条线，而 Helios 这类机架的宿主 CPU 恰恰决定了整机的喂数据能力。两家隔空对喷 benchmark 的部分也很有看头。

## [Raymond Chen 讲滚动条快捷键简史：一个他自己也是最近才知道的操作](https://devblogs.microsoft.com/oldnewthing/20260922-00/?p=112719/)

Windows 头二十年里滚动条只有五个鼠标目标：两端箭头（按行滚）、滑块与箭头之间的两段空白（按页滚）、以及滑块本身。Windows 7 给它加了右键菜单，七项中六项对应既有操作，唯一的新操作是「滚动到此处」——直接右键点你想去的位置即可，不必关心当前在哪。同时还加了一个更隐蔽的快捷方式：按住 Shift 点击滚动条，滑块直接跳到点击处。Chen 坦承「我最近才知道这个快捷键，一直用的是我那个可靠的右键菜单」。如今的割裂局面是：Win32 两者都有，WPF 看起来也都有，Chromium 只实现了 Shift+click，WinUI「令人沮丧地两个都没有」，Qt 则把它拆成三个样式提示交给应用开发者自己决定。评论区里当年写下 Chromium 第一版滚动条实现的 Peter Kasting 补充更正：Shift+click 其实在 Windows XP 就有了。

**推荐理由**：一段很典型的桌面 UI 考古——文章本身在讲功能怎么加进来的，评论区又把时间线往前推了一代。结尾那句「等我终于学会一个快捷键，生态已经碎到我没法指望它能用」也相当应景。
