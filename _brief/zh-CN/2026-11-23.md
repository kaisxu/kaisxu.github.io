## [OpenAI 提议用困惑度设立共同安全门槛，但代码预测不等于通用智能](https://openai.com/index/perplexity-and-intelligence/)

*研究观点发布：11 月 22 日；由 HN 讨论追溯至原文。*

OpenAI 首席科学家 Jakub Pachocki 公布内部固定代码集上的预训练损失变化，建议实验室以困惑度等指标设定共同开发门槛，在监测能力达标前不跨越。他同时承认跨机构数据不可比、推理增强未被覆盖等局限。当天的[反方分析](https://micjm.com/blog/lowering-perplexity-without-scaling/)指出，提高代码训练占比也能改善这类指标，因此曲线不能直接证明通用能力增长；这仍是治理提议，并非已达成的行业协议。

**推荐理由**：它可能影响前沿模型的安全评估与开发节奏；同时阅读原提案与指标批评，有助于区分能力证据和政策主张。

## [数字化汽车的维修壁垒：美国消费者每年额外成本被估至 120 亿美元](https://www.theregister.com/personal-tech/2026/11/22/as-cars-go-digital-us-consumers-pay-an-extra-12-billion-a-year-for-repairs/5311412)

*报道发布：11 月 22 日 16:08 UTC；消费者组织报告解读。*

《The Register》引述消费者组织 PIRG 的调查：维修厂为诊断汽车、释放电子驻车制动等操作，需要购买软件权限并等待下载、登录，独立店还可能被迫转单。报告将全行业每年约 8300 万小时的接入摩擦折算为约 120 亿美元成本，并主张标准化诊断接入和车主数据授权。这是倡议组织的估算，不能把保险涨价全部归因于软件收费；[原始报告](https://www.repair.org/closing-shop/)也区分了相关性与因果。

**推荐理由**：软件锁定正在改变实体设备的所有权与维修市场；其影响不止汽车，也能帮助理解智能硬件的长期使用成本。

## [一周合并上百个 PR 之后：AI 编程的瓶颈转向验证、编排与复杂需求](https://lethain.com/passing-100-prs-in-a-week/)

Will Larson 复盘 Imprint 的智能体开发流程：从清理过期文档、结构化工单，到云端运行环境、自动验证与任务分流，逐步提高交付吞吐。他报告单周合并 115 个 PR，最高连续七天为 170 个，但明确表示 PR 数不是价值指标，许多改动比资深工程师处理的任务简单。当前难点已转向复杂产品判断、验证覆盖和减少人工编排，而非简单取消代码审查。

**推荐理由**：这是带业务约束的工程案例，而非只展示生成速度；适合观察 Agent 真正落地时，组织流程如何成为主要限制。

## [GitHub Actions 接受不合规范的 YAML，严格检查器反而无法兼容](https://yossarian.net/til/post/github-actions-accepts-invalid-yaml/)

*维护者技术分析发布：11 月 22 日；不是新披露的代码执行漏洞。*

zizmor 维护者 William Woodruff 发现，Actions 接受某类缩进不足的单引号多行字符串，但符合 YAML 规范的解析器会拒绝它。他此前曾让 tree-sitter-yaml 兼容这种写法，如今确认错误后提出撤销修补。文章给出最小示例，并追踪 YamlDotNet 的对应行为；问题体现了实际平台与标准之间的分歧，不应据此断言所有工作流有漏洞或 GitHub 已修复。

**推荐理由**：影响工作流审计、静态分析和跨工具兼容性；解析器意见不一致时，应核对规范和最小复现，而不是盲信平台能运行。

## [阿里巴巴与中科院：用定向练习把慢推理变成游戏智能体的快速判断](https://arxiv.org/abs/2611.26007)

*System-One RSI；11 月 19 日投稿、11 月 20 日进入 arXiv 公告，预印本；项目展示早于本窗口。*

阿里巴巴与中科院自动化所团队让推理智能体提供规则和监督，再将练习经验写入决策模型，由控制器执行动作，不必每步生成思维链。《绝区零》实验中，适配后的 27B 模型在五局测试里全部获胜，对照为两局，决策中位耗时约 230 毫秒。但样本很小，训练与验证共享来源局次，不能证明独立场景泛化；这是一种受指导的任务适配，而非已实现无限自我提升。

**推荐理由**：切中实时 Agent 的延迟与定制化问题；论文也披露评估限制，适合研究怎样把离线推理投入转化为在线动作能力。

## [aaf-gate 首个候选版：用纯 Python 给智能体工具调用加权限闸门](https://github.com/buberlo/aaf-gate/releases/tag/v1.0.0rc1)

*版本发布：11 月 22 日 21:43 UTC；实验性项目。*

aaf-gate 在既有智能体运行时前加入确定性策略，把工具调用区分为读取、起草和内部写入，提供调用次数限制、停止开关及 SQLite 哈希链审计日志。核心只依赖 Python 标准库，目前适配 Hermes，试点限定 Gmail 读取、分类和草拟回复，不包含发送。作者明确标注尚未完成目标设备验收、未获相关预览访问，不能把本地单测通过理解为已可安全投产。

**推荐理由**：把权限判断从模型提示词移到可检查的代码层，适合学习 Python Agent 的最小权限设计；现阶段应作为原型评估。

## [Debian 重整 iperf 工具包装，并引入可并发压测的 fireperf](https://blog.daniel-baumann.ch/posts/20261122-1.html)

*维护者文章发布：11 月 22 日；介绍近期已完成的打包工作。*

Debian 维护者 Daniel Baumann 将 iperf、iperf3 的客户端与服务器拆包，为服务端加入动态用户、systemd 加固与防火墙集成，并用实例模板简化多个 iperf3 服务的管理。新引入的 fireperf 支持同端口多客户端、双向流量、JSON 输出及实时终端图表，还可兼容既有测速服务。软件包已进入 sid；文中提及的稳定版回移来自 Debian Fast Forward，不能当作默认仓库已经更新。

**推荐理由**：网络压测工具的部署方式直接影响基础设施测试效率与暴露面；这次更值得关注的是并发能力和服务端默认配置。

## [Rust 项目 Straum 更新：同一事实表只加载一次，持续维护多个聚合视图](https://github.com/janbjorge/straum)

*代码更新：11 月 22 日 16:34 UTC；当日 HN 展示，非当天首次创建。*

Straum 是 PostgreSQL 旁的 Rust 聚合服务，从复制流持续更新时间桶与分组结果，不要求在数据库中添加扩展或触发器。本次提交将同一事实表供多个视图使用时的初始加载合并，避免重复复制。查询返回数据推进到的时间，便于判断新鲜度；但服务只支持其声明的查询子集，全部状态保存在内存，重启须重新加载，且作者明确表示接口尚不稳定。

**推荐理由**：适合关注 Rust 数据基础设施的人研究增量计算与数据库卸载；收益需与内存占用、重启成本和复制权限一起评估。

## [LocalCode 0.5.43：本地编程智能体补齐 Metal 推理与模型管理细节](https://github.com/mjwsolo/localcode/releases/tag/v0.5.43)

*版本发布：11 月 22 日 15:43 UTC。*

**推荐理由**：展示本地 Agent 可用性常取决于模型格式、内核和缓存的细节，而不只是权重大小；也适合检查一体化 Python 工具的边界。

## [Gall 0.1.0：用 Rust 管理本地模型，让 Mac 在回答之间归还内存](https://github.com/ltrgoddard/gall/releases/tag/v0.1.0)

*版本发布：11 月 22 日 21:36 UTC。*

Gall 面向 24GB Apple Silicon Mac 提供 Inkling 2 Mini 本地服务和菜单栏界面，通过空闲卸载、保存可复用会话状态，再按需加载来减少常驻内存。作者测得回答后的空闲服务约占 51—57MB，但推理时仍需约 18GB 预算，不能理解成几十兆就能运行模型。项目用 Rust 构建、提供兼容接口；性能仅来自单机若干次运行，当前发行包也尚未获苹果公证。

**推荐理由**：相比只谈量化比例，它关注普通笔记本还要同时工作时的内存体验；值得研究加载延迟、状态复用与峰值资源的权衡。

## [从 Pentium Pro 到 DOOM：重新理解 P6 的微操作执行层](https://nand2mario.github.io/posts/2026/p6_basics/)

*逆向研究文章发布：11 月 22 日；研究对象始于 1995 年。*

nand2mario 结合社区微码转储与工具，解释 P6 如何把 x86 指令译成内部微操作，并分析解码、标志位、控制流和宏别名。文章展示顺序执行的 C 微操作模拟器启动 MS-DOS、运行 DOOM，说明这一层本身已构成完整执行架构。它不是周期精确的乱序处理器复刻；文中也区分了 Pentium Pro 的 ROM 数据与用于展示布局的 Pentium II 芯片照片。

**推荐理由**：符合 2010 年前计算机史兴趣，且有微码、模拟器与运行结果作支撑，比单纯回顾芯片规格更能解释架构演进。
