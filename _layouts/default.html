--- layout: compress --- {%- comment -%} LOCAL OVERRIDE of Chirpy v7.6.0's _layouts/default.html. Two changes from the theme's copy; everything else is verbatim. 1. `` resolves through `lang.html` (the `lang` variable) instead of reading `site.lang` directly. The theme's chain — `page.lang | default: site.alt_lang | default: site.lang` — predates polyglot and never consults `site.active_lang`, so every page of the /en/ site declared `lang="zh-CN"`. That misinforms screen readers, browser translation prompts, and search engines about the language of the text they are looking at. Note this deliberately reports the language of the *build*, not of the text. A fallback page (untranslated, so showing Chinese under /en/) will claim `lang="en"`. Both options are wrong for a fallback page; this one is wrong in the direction that keeps a language's pages self-consistent, and the canonical link already points such pages back at the original. 2. `include_cached` → `include` for the three chrome includes that take a `lang=` parameter (update-list, trending-tags, footer, search-results, notification, search-loader). Jekyll's include cache keys on the include name and parameters, but these render `site.data.locales[lang]` lookups whose results differ per language while the parameters stay textually identical — the first language built would otherwise win and its strings would leak into the other language's pages. When bumping the chirpy gem, re-diff this file and re-apply. {%- endcomment -%} {% include origin-type.html %} {% include lang.html %} {% include head.html lang=lang %} {% include sidebar.html lang=lang %}
